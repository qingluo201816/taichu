# Skill 编排规范

## 适用范围

用于 `prd-to-plan`、`prd-spec-develop` 这类多阶段编排 Skill。

## 编排职责

编排 Skill 只负责：

- 校验输入。
- 确定阶段顺序。
- 调用或指引子 Skill。
- 展示阶段摘要。
- 等待用户确认。
- 汇总失败与后续动作。

编排 Skill 不直接替代子 Skill 的职责，不在用户未确认时进入下一阶段。

## 确认闸门

以下节点必须等待用户确认：

- 功能点清单生成后。
- 规格初始化后。
- 需求文档生成后。
- 设计文档生成后。
- 任务清单生成后。
- 代码实现与验证完成后。

当前环境没有专用提问工具时，用普通中文问题等待用户回复。

## 失败处理

子阶段失败时，必须展示：

- 失败阶段。
- 失败原因或命令输出摘要。
- 已生成或已修改的文件。
- 可选处理：重试、跳过当前规格、终止流程。

不得把失败阶段描述为完成。

## 太初项目约束

- 遵循 `AGENTS.md` 的不可变决策。
- Python 命令使用 `uv run python`。
- 不引导多小说、多租户或 `project_id`。
- 不自动回滚用户已有改动。
- 涉及前端时先读取 `TAICHU_DESIGN.md` 和 `.agents/skills/taichu-ui-components/SKILL.md`。
