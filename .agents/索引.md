# 太初 Codex 开发态索引

> 更新日期：2026-07-18

`.agents/` 是太初唯一的项目级 Codex 工作流目录。项目不再维护 `.claude/`、Claude 命令、Claude Agents 或第二套 Skills。

## 去哪里看

| 需求 | 位置 |
|---|---|
| Skill 编写与修改规则 | `.agents/skills/rule.md` |
| 某个 Skill 的触发与流程 | `.agents/skills/{名称}/SKILL.md` |
| Skill 自带详细规则 | 对应 Skill 的 `references/` |
| Skill 自带确定性脚本 | 对应 Skill 的 `scripts/` |
| 项目级启动、评测与维护脚本 | `.agents/scripts/` |
| PRD 分析中间计划 | `.kiro/plans/{版本号}/` |
| cc-sdd 规格 | `.kiro/specs/{版本号}/{功能名}/` |
| 全仓资料地图 | 根目录 `README.md` |

## Skill 清单

### 日常入口

| Skill | 用途 |
|---|---|
| `taichu-task-package-execution` | 执行已经明确的开发任务包 |
| `taichu-acceptance-brief` | 整理中文验收摘要与手动验收路径 |
| `taichu-git-publish` | 仅在用户明确授权后提交和推送 |
| `taichu-ui-components` | 前端组件复用、外部组件准入和验证 |

### PRD 与规格流程

| Skill | 用途 |
|---|---|
| `prd-to-plan` | PRD 到规格与实现的总编排入口 |
| `prd-plan-analyze` | 拆分功能点并写入 `.kiro/plans/` |
| `prd-spec-develop` | 编排规格初始化、设计和实现 |
| `prd-to-ccsdd` | 生成规格初始化文件和需求 |
| `prd-design-generator` | 生成技术设计并执行设计评审 |
| `prd-spec-impl` | 生成任务、等待确认并按 TDD 实现 |

## PRD-to-Plan 调用链

```text
prd-to-plan
├── prd-plan-analyze
│   └── .kiro/plans/{版本号}/功能点清单.md
└── prd-spec-develop
    ├── prd-to-ccsdd
    ├── prd-design-generator
    └── prd-spec-impl
        └── .kiro/specs/{版本号}/{功能名}/
```

`prd-docs/` 只是用户明确启动 PRD 流程时的输入暂存目录，按需创建，不使用 `.gitkeep`。仓库中的未确认产品设想统一放在 `docs/临时产品文档/`，不能直接当作 PRD 执行。

## 强制边界

- 所有 Skill 服从根目录 `AGENTS.md`。
- 前端任务先读取根目录 `DESIGN.md`，再使用 `taichu-ui-components`。
- 修改 Skill 前先读取 `.agents/skills/rule.md`，修改后运行 `quick_validate.py`。
- 目录由流程按需创建，不创建 `.gitkeep`。
- 任务完成不代表获得 Git 发布授权；只有用户明确要求时才提交或推送。
- 完成任务包不在 `.agents/` 长期归档；需要追溯时使用 Git 历史或明确的历史资料目录。
