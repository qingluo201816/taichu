# 太初 Codex 开发态索引

> 更新日期：2026-08-30

`.agents/` 是太初唯一的项目级 Codex Skill 目录；`.codex/` 只保存 Codex 原生自定义 Agent 与客户端配置。项目不再维护旧客户端命令、旧 Agent 定义或第二套 Skills。

## 去哪里看

| 需求 | 位置 |
|---|---|
| Skill 编写与修改规则 | `.agents/skills/rule.md` |
| 某个 Skill 的触发与流程 | `.agents/skills/{名称}/SKILL.md` |
| Skill 自带详细规则 | 对应 Skill 的 `references/` |
| Skill 自带确定性脚本 | 对应 Skill 的 `scripts/` |
| 项目级启动、评测与维护脚本 | `.agents/scripts/` |
| Codex 自定义 Agent | `.codex/agents/*.toml` |
| codex-sdd 规格与恢复状态 | `.sdd/specs/{版本号}/{大需求模块名称}/` |
| 全仓资料地图 | 根目录 `README.md` |

## Skill 清单

### 日常入口

| Skill | 用途 |
|---|---|
| `taichu-task-package-execution` | 执行已经明确的开发任务包 |
| `taichu-acceptance-brief` | 整理中文验收摘要与手动验收路径 |
| `taichu-git-publish` | 仅在用户明确授权后提交和推送 |
| `taichu-ui-components` | 前端组件复用、外部组件准入和验证 |

### 规格流程

| Skill | 用途 |
|---|---|
| `codex-sdd` | 自动编排规格初始化、需求、设计、任务、实现、独立校验和会话恢复 |

## Codex SDD 调用链

```text
$codex-sdd run {版本号} {大需求模块名称} {需求描述}
├── spec-init                     # 主 Agent 初始化与恢复状态
├── codex_sdd_requirements
│   └── codex_sdd_validator       # 需求独立校验
├── codex_sdd_gap_validator       # 存量差距分析
├── codex_sdd_design
│   ├── codex_sdd_design_reviewer # 设计质量 GO/NO-GO
│   └── codex_sdd_validator       # 设计独立 PASS/FAIL
├── codex_sdd_tasks
└── codex_sdd_impl                # 仅在明确要求实现时
    └── codex_sdd_impl_validator  # 实现独立校验
        └── .sdd/specs/{版本号}/{大需求模块名称}/
```

`run` 默认连续推进到任务清单；用户明确要求实现或带 `--impl` 时继续到代码与实现校验。流程不在阶段间例行审批，只有实质歧义、额外权限或重复校验失败才暂停。`prd-docs/` 只是用户明确提供 PRD 时的输入暂存目录，按需创建，不使用 `.gitkeep`。仓库中的未确认产品设想统一放在 `docs/已讨论功能/`，不能直接当作已确认需求执行。

原始参考包 56 个非空文件的一对一落点记录在 `.agents/skills/codex-sdd/references/migration-ledger.md`。框架修改后必须运行 `scripts/validate_framework.py` 和 `scripts/self_test.py`，防止严格规则再次被压缩或状态契约失效。

## 强制边界

- 所有 Skill 服从根目录 `AGENTS.md`。
- 前端任务先读取根目录 `DESIGN.md`，再使用 `taichu-ui-components`。
- 修改 Skill 前先读取 `.agents/skills/rule.md`，修改后运行 `quick_validate.py`。
- codex-sdd 的状态与产物只写入 `.sdd/`，不创建旧框架运行目录。
- 目录由流程按需创建，不创建 `.gitkeep`。
- 任务完成不代表获得 Git 发布授权；只有用户明确要求时才提交或推送。
- 完成任务包不在 `.agents/` 长期归档；需要追溯时使用 Git 历史或明确的历史资料目录。
