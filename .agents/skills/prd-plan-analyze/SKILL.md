# PRD Plan Analyze

## 定位

读取 `prd-docs/` 中的 PRD 文档，拆分为结构化功能点清单，输出到 `.kiro/plans/{版本号}/功能点清单.md`。

## 输入

- PRD 文件名：`prd-docs/{文件名}`，支持 `.md`、`.txt`、`.pdf`、`.docx`。
- 版本号：例如 `V1.0`。

## 输入校验

执行前必须确认：

1. PRD 文件存在。
2. 版本号非空。
3. 文档内容非空。

任一校验失败时立即停止，并用中文说明需要用户补充什么。

## 读取方式

- `.md`、`.txt`：直接读取文本。
- `.pdf`、`.docx`：优先使用当前环境可用的文档读取能力；如需提取嵌入图片，运行：

```bash
uv run python .agents/skills/prd-plan-analyze/scripts/extract_images.py prd-docs/{文件名} --output .kiro/plans/{版本号}/prd_images
```

图片中的结构化信息必须转写为中文需求说明，不能只引用图片路径。

## 拆分规则

先读取 `references/function-split.md`，再按其中规则拆分。核心标准：

- 单一业务操作：一个功能点只做一件事。
- 状态机边界：按业务对象生命周期状态拆分。
- 依赖无环：功能点依赖必须是有向无环图。
- 测试可构造：前置条件可构造，预期结果可验证。

## 输出格式

输出文件：`.kiro/plans/{版本号}/功能点清单.md`。按需创建目录，不创建 `.gitkeep`。

必须按 PRD 一级需求模块分组，每个模块下按“新增功能”“功能增强”“功能不变”分类；“功能不变”仅在确实存在时输出。

```markdown
# 功能点清单

## 文档信息
| 字段 | 内容 |
|---|---|
| 版本号 | {版本号} |
| PRD 文件 | {文件名} |
| 创建日期 | {YYYY-MM-DD} |
| 涉及模块 | {模块列表} |

---

# 一、{大需求模块名称}

## 1.1 新增功能
| 序号 | 功能点 | 所属模块 | PRD 需求描述 | 前置条件 | 预期结果 | 依赖功能点 | 代码影响 |
|---|---|---|---|---|---|---|---|
| 1.1-1 | 新增 XXX | {模块名} | {需求描述} | 无 | {可验证结果} | 无 | {影响范围} |

## 1.2 功能增强
| 序号 | 功能点 | 所属模块 | 现有功能描述 | 增强范围 | 前置条件 | 预期结果 | 依赖功能点 | 代码影响 |
|---|---|---|---|---|---|---|---|---|

## 1.3 功能不变
| 序号 | 功能点 | 所属模块 | 现有功能描述 | 无需改动原因 |
|---|---|---|---|---|
```

序号格式为 `{大模块序号}.{分类序号}-{功能点序号}`，例如 `2.1-3`。

## 展示前校验

展示给用户前必须检查：

- 前置条件可构造。
- 预期结果可验证，不使用主观描述。
- 依赖关系无循环。
- 功能点粒度合理，不用“且”“同时”等连接词把多个功能揉在一起。

校验不通过时先重新拆分，再展示给用户确认。
