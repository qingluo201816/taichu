# `status` 与 `resume`：状态检查和恢复

## `status` 使命

只读展示规格的磁盘事实、证据有效性、下一个可执行阶段和阻塞项。

## 参数

```text
$codex-sdd status [<版本号>/<大需求模块名称>]
$codex-sdd resume [<版本号>/<大需求模块名称>]
```

未指定规格时：

- 读取 `.sdd/state.json.active_spec`；
- 若不存在合法活动规格，列出所有规格并要求明确选择；
- 不从聊天历史猜测。

## 状态读取步骤

1. 运行 `state.py show [--spec <id>]`。
2. 运行 `state.py validate --spec <id>`。
3. 检查规格目录实际文件。
4. 统计：
   - 数字需求与验收标准；
   - 设计组件、契约与需求覆盖；
   - 任务总数、完成、进行中、待办；
   - 每个独立校验的结论、轮次、对象哈希和是否失效；
   - `target_phase`、`status`、`blocker`。
5. 比较 `.sdd/state.json` 与规格 `spec.json`；索引漂移只报告，不在纯 `status` 中自动修改。

## 状态报告

```text
规格：...
当前阶段：...
目标阶段：...
总体状态：active | blocked | completed
状态一致性：PASS | FAIL

阶段证据：
- 初始化：...
- 需求：文件 / 独立结论 / 哈希状态
- 设计：文件 / 评审 / 独立结论 / 哈希状态
- 任务：总数与状态
- 实现：报告 / 独立结论

阻塞项：...
下一可执行操作：...
恢复命令：...
```

百分比只用于任务复选框等可机械计算项目；不得为文档质量编造百分比。

## `resume` 执行

1. 完成上述状态检查。
2. 索引漂移时运行 `repair-index`，再验证。
3. 根据 `target_phase` 和门禁证据找到第一个未完成阶段。
4. 重新读取该阶段完整命令、Agent、规则和模板。
5. 继续自动阶段循环，直到原目标或真实阻塞。
6. 已验证且对象哈希有效的阶段不得重做。
7. 已完成任务先核对实际代码和测试证据，再跳过。

## 失败处理

- 规格不存在：列出 `.sdd/specs/` 中可用规格。
- `spec.json` 损坏：停止恢复，报告解析错误和文件路径。
- PASS 报告哈希失效：回到相应独立校验。
- `tasks-status.json` 与 `tasks.md` 不一致：先修状态，不进入实现。
- `target_phase` 缺失：报告状态损坏，不擅自扩大目标。
