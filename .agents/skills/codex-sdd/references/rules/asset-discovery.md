# 现有资产探查规则

## 适用范围

在编写任何 `requirements.md` 或 `design.md` 之前强制执行。目标是避免重复建设、区分现有与计划新增、识别影响面，并防止新规格破坏太初现有能力。

## 零、强制原则

- 禁止跳过探查直接写需求或设计。
- 禁止用“应该已有”“通常会有”替代事实。
- 必须基于当前权威资料、源码、测试、配置或可复现命令。
- Graphify 是可选派生证据，不是前置依赖或事实源。
- 使用 Graphify 前必须读取 `graphify-out/.graphify_root` 并确认扫描根覆盖目标；不覆盖时不得引用图谱结论。
- Git 状态、当前 diff 与历史只能作为可复查证据使用，不能覆盖工作树里的当前源码事实。
- 必须明确标注：`现有`、`计划新增`、`未知/需确认`。
- 需求阶段把结论写入“现有资产探查”；设计阶段把详细证据写入 `research.md` 并在 `design.md` 汇总结论。

## 一、项目事实源查阅（宏观）

### 必须读取

1. 根 `AGENTS.md`：项目定位、不可变决策、数据宪法、技术栈、启动和联动规则。
2. 根 `README.md`：仓库地图与资料入口。
3. 与需求直接相关的最新项目资料。
4. 涉及 `docs/`、项目 Skill 或前端时的对应强制规则。
5. 涉及 UI 时根 `DESIGN.md`。

`docs/历史/` 仅作历史证据，不参与当前决策；临时架构/产品资料必须按状态判断，不得覆盖当前代码事实。

### 探查目标

- 需求是否已有当前功能说明或历史决策？
- 现有业务流程、数据事实源和生命周期是什么？
- 哪些范围已明确排除？
- 哪些接口、集合、页面、Agent 或 Tool 可能受影响？
- 是否触发启动脚本、README 地图、project_assets 说明或技术栈联动？

### 记录

| 资料 | 状态 | 关键事实 | 对规格影响 |
|---|---|---|---|
| `AGENTS.md` | 当前规则 | ... | ... |
| 相关资料路径 | 当前/临时/历史 | ... | ... |

无匹配资料时明确写“无当前功能资料”，随后通过代码确认。

## 二、代码与测试探查（微观）

### 文件与文本

优先使用：

```powershell
rg --files
rg -n "<业务词|符号|端点|字段>" src web tests
```

根据实际语言和目录缩小范围，不照抄不存在的 Java/Vue 路径。

### 后端检查

按需求相关性确认：

- `domain`：领域模型、值对象、Protocol，不应依赖 Agent/LLM/MCP/存储实现；
- `application`：服务、Agent 协议、能力注册与业务编排；
- `infrastructure`：存储、动态发现、LLM/MCP 适配；
- FastAPI 路由与 DTO；
- MongoDB 集合、校验器与索引；
- LangGraph/runtime 节点与真实能力注册；
- 测试、评测集、Prompt 渲染和启动配置。

特别检查：

- 是否误引入 SQLite/FTS；
- AI 是否绕过候选校验直接写 MongoDB；
- 知识卡字段是否违反已废弃字段规则；
- 能力目录与单次运行 DAG 是否混淆；
- 新 Agent 是否可通过插件发现而无需改已有注册代码。

### 前端检查

涉及 UI 时执行 `frontend-exploration-rules.md`，至少确认：

- `web/src/app/<route>/page.tsx` 路由入口；
- 页面使用的 feature shell/业务组件；
- `web/src/lib/api/*.ts` API 调用；
- `web/src/lib/types/*.ts` 契约；
- 本地状态、hooks 与交互；
- `components/ui/`、motion primitives 和已有视觉组件可复用性；
- `DESIGN.md` 的页面模式、token、动效和禁止项；
- 用户可见中文文案；
- 桌面交付边界。

### 测试与运行检查

- 查找与目标相关的单元、集成、评测和前端测试。
- 查找 `pyproject.toml`、`web/package.json` 中真实命令。
- 识别是否触发 `start.bat` 验证。
- 确认固定端口和服务复用规则。

## 三、Graphify 关系探查

### 使用条件

仅当以下条件均满足时使用：

1. `graphify-out/graph.json` 存在；
2. `.graphify_root` 存在并覆盖目标路径；
3. 图谱未明显过期或损坏；
4. 当前 Graphify Skill/CLI 可用。

当前图谱若只覆盖 `src/`，不得用它宣称已分析 `web/`、`.agents/` 或其他未覆盖目录。

### 查询方式

使用当前接口：

```text
graphify query "<自然语言问题>"
graphify path "<节点A>" "<节点B>"
graphify explain "<节点>"
```

查询前用图谱词汇扩展问题。引用具体事实时记录 `source_location`。

### 复核要求

- 关键节点、调用链和依赖方向必须回到源码/测试复核。
- 图谱与源码冲突时，以当前源码和测试为准并记录图谱可能过期。
- 图谱不可用时直接降级到 `rg`、文件阅读和测试，不视为阻塞。
- 不使用个人项目不存在的图谱服务或旧查询脚本。

## 四、影响面核对

每个核心对象逐项检查：

| 探查项 | 发现 | 证据 | 对需求/设计的影响 |
|---|---|---|---|
| 已有相关模块 | ... | 文件:行号/符号 | 复用/扩展/不得修改 |
| 上游调用方 | ... | ... | 兼容性 |
| 下游依赖 | ... | ... | 允许依赖 |
| 数据所有权 | ... | ... | 事实源/生命周期 |
| API/契约 | ... | ... | 保持/新增/迁移 |
| 测试 | ... | ... | 回归范围 |
| 启动与配置 | ... | ... | 联动验证 |
| 前端资产 | ... | ... | 复用/修改/新增 |
| Graphify 覆盖 | 覆盖/不覆盖/不可用 | ... | 查询或降级 |

## 五、代码验证兜底

对仍不确定的类、函数、字段、端点、集合、页面和配置：

1. `rg -n` 精确搜索；
2. 读取定义与直接调用方；
3. 读取相关测试；
4. 读取序列化/校验边界；
5. 对外部契约查当前官方一手资料；
6. 无法确认则标“未知”，不得写成现有事实。

## 六、前端触发条件

以下任一情况必须执行完整前端探查：

- 新增/修改页面、导航、弹窗、表单、卡片、工作台或编辑器；
- 修改用户可见文案、状态、错误提示或操作流程；
- 新增/修改前端 API 与类型；
- 使用动效、视觉效果或组件库；
- 后端契约变化会影响 UI。

## 七、完成门禁

探查完成必须同时满足：

- 项目事实源已查；
- 相关代码和测试已查；
- 现有/新增/未知已区分；
- 数据与依赖边界已确认；
- UI 范围按当前规则调查；
- Graphify 覆盖情况明确；
- 每个重要结论有证据；
- 结果已写入对应规格产物。

任一核心事实仍只能靠猜测时，不得进入正式需求或设计。
