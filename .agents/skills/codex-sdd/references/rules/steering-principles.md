# 项目事实源维护原则

## 适配定位

太初已有权威项目资料，不创建平行的项目记忆目录。本规则约束 `project-context` 与 `project-context-custom` 对现有事实源的审计和增量同步。

## 一、权威资料

- 根 `AGENTS.md`：项目定位、不可变工程决策和强制规则。
- 根 `README.md`：面向开发者的仓库地图和资料入口。
- 根 `DESIGN.md`：唯一前端视觉规则源。
- 目录内 `AGENTS.md`/`rule.md`：局部范围规则。
- `docs/` 最新资料：当前/临时/历史按 `docs/rule.md` 区分。
- `project_assets/readme.md`：该目录职责说明。

`.sdd/` 是规格运行状态，不是项目长期事实源。

## 二、黄金法则

> 如果新代码遵循已有稳定模式，项目事实源通常不需要更新。

应记录模式、边界、决定和理由，不记录详尽文件列表。

### 应记录

- 产品定位与范围；
- 架构分层和依赖方向；
- 数据事实源和生命周期；
- 技术栈与关键工具链；
- 启动、验证和联动规则；
- 命名/组织模式；
- 已废弃技术和防回归边界；
- 具有长期意义的决策理由。

### 不应记录

- 每个文件或组件的目录；
- 每个依赖；
- 单次任务进度；
- 开发阶段/成熟度/讨论轮次；
- 自动化工具内部目录细节；
- 会话承诺或临时待办；
- 密钥、密码、令牌、数据库 URL、内部地址或个人信息。

## 三、单一归属

同一事实只有一个权威位置：

- 全项目不可变规则 → `AGENTS.md`；
- 仓库入口 → `README.md`；
- 前端视觉 → `DESIGN.md`；
- 子系统局部规则 → 最近层级规则；
- 未确认/历史资料 → `docs/` 对应状态目录；
- project_assets 职责 → `project_assets/readme.md`。

其他文件引用，不复制整段。发现重复时先确定权威归属，再清理过期副本。

## 四、同步流程

1. 读取全部相关权威资料。
2. 调查真实代码、测试、配置和启动。
3. 分类：
   - 事实一致；
   - 资料过期；
   - 代码偏离规则；
   - 新稳定模式；
   - 未决建议；
   - 规则冲突。
4. 确定正确目标文件。
5. 先报告拟更新内容和证据。
6. 用户明确要求同步时使用最小增量补丁。
7. 保留用户自定义章节与示例。
8. 更新资料入口和“最后更新”信息（适用时）。
9. 复核不含敏感信息或单次任务状态。

## 五、模板使用

`assets/project-context/` 是结构提纲，不是项目事实。每条内容落盘前必须由以下之一支持：

- 现有项目规则；
- 真实代码/测试/配置；
- 用户明确作出的新决策。

不得直接复制通用 REST、安全、数据库或部署示例并宣称已采用。

## 六、目录规则

- 修改 `docs/` 前读 `docs/rule.md`。
- 修改项目 Skill 前读 `.agents/skills/rule.md`。
- 修改前端规则或讨论 UI 前读 `DESIGN.md`。
- 新增/移动/删除资料入口时同步根 `README.md`。
- 不创建 `.gitkeep`。
- 不建立第二套产品/技术/结构项目记忆目录。

## 七、质量

- 单一主题；
- 说明理由；
- 规则可执行且可验证；
- 示例来自当前项目或明确标为示例；
- 增量而非全量覆盖；
- 语言中文；
- 不含工时或排期；
- 与更高优先级规则一致。
