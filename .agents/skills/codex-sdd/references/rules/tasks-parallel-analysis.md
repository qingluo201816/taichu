# 并行任务分析规则

## 目的

在生成 tasks.md 时，提供一致的方法来识别可以安全并行执行的任务。  

## 与任务排序的关系

(P) 表示：此任务不依赖于其紧邻的前置同级任务，可以与它们并发运行。任务排序原则（见 tasks-generation.md）确保基础阶段任务首先运行，使核心阶段任务成为主要的 (P) 候选。  

## 何时认为任务可以并行

仅当所有以下条件满足时，才将任务标记为可并行：  

无数据依赖：对待处理任务无数据依赖。  
无冲突文件或共享可变资源：不触及冲突的文件或共享可变资源。  
无需前置审查/批准：不需要另一个任务的前置审查或批准。  
基础工作已完成：此任务所需的环境/设置工作已由先前的基础阶段任务满足。  
边界不重叠：_Boundary:_ 标注确认任务在独立的组件上运行。  

## 标记约定

在每个符合条件的任务的数字标识符后立即附加 (P)。  
示例：- [ ] 2.1 (P) 构建邮件后台工作器  
适用于主任务和子任务（如适用）。  
如果请求顺序执行（如通过 --sequential 标志），完全省略 (P) 标记。  
保持 (P) 在复选框括号外部，以避免与完成状态混淆。  

## 分组和排序指南

当工作属于同一主题时，将并行任务分组在同一父级下。  
在详情子弹中列出明显的前提条件或注意事项（如"需要来自 1.2 的模式迁移"）。  
当两个任务看起来相似但不是并行安全时，显式调用阻塞依赖。  
跳过仅作为容器的主任务（没有自己的可执行详情子弹）的 (P) 标记——在子任务级别评估并行执行。  

## 质量检查清单

在用 (P) 标记任务之前，确保：  

已验证并发运行此任务不会产生合并或部署冲突。  
已确认 _Boundary:_ 标注显示非重叠的组件范围。  
已在详情子弹中捕获任何共享状态期望。  
已确认实现可以独立测试。  
如果此 (P) 任务仍需要来自不同主任务组的特定先前工作，添加 _Depends: X.X_。  
如果任何检查失败，不要用 (P) 标记任务，并在任务详情中解释依赖。
