# 设计综合

在发现之后、编写设计文档之前，应用以下三个视角来审视收集到的发现。此步骤需要全局视角——不要并行化。  

### 1. 泛化

将所有需求作为一个整体来审视。识别多个需求是否是同一底层问题的变体。  

如果功能 A 是更通用能力 X 的特例，则设计 X 并使其接口自然地支持 A（以及潜在的 B、C）  
保持实现范围在当前需求所要求的范围内——泛化接口，而非实现  
将识别出的泛化记录到 research.md 的设计决策章节中  

### 2. 构建 vs 采用

对于新兴设计中的每个主要组件，问：这个问题是否已有解决方案？  

搜索已建立的标准（RFC、协议）、经过实战检验的库或平台原生能力，看是否能满足需求  
当现有解决方案无需重大适配即可满足需求时，优先采用而非自建  
如果采用：验证解决方案是否积极维护、与项目技术栈兼容（检查 steering），并满足非功能需求  
如果自建：记录拒绝现有方案的理由（捕获到 research.md 中）  

### 3. 简化

对于新兴设计中的每个组件和抽象层，问：这是必要的吗？  

移除"以防万一"或为当前规格中不存在的假设性未来需求而存在的组件  
扁平化不必要的抽象层——如果一个接口只有一个实现且可预见的未来不会有第二个，它可能不需要这层间接  
优先选择少量内聚的组件，而非大量细粒度的组件  
正确的设计是满足所有需求且在接口层面保持可扩展的最小设计
