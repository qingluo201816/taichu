# 独立校验门禁

## 目的

通过隔离上下文和“先独立发现、再读取目标”的顺序，避免生成者的措辞和假设影响校验结论。

## 一、共同门禁

- 顺序不变量是“先发现、先落盘，后读取目标、后对比”；任何倒序都会使本轮校验无效。
- 独立校验必须由不同角色/新上下文执行。
- 输入必须含 mode、规格标识、规格目录和目标对象。
- 校验 Agent 不得修复被校验对象。
- 所有结论必须有证据。
- 报告必须记录目标 SHA-256；目标变化使结论失效。
- 报告结尾必须是精确 `结论：PASS` 或 `结论：FAIL`。
- discovery 作为审计证据保留。

## 二、requirements 模式

### 阶段一禁止读取

- `requirements.md` 的任何内容；
- 需求摘要、目录、标题、片段或其他 Agent 的转述；
- 设计、任务和基于目标生成的派生产物。

### 阶段一允许读取

- `spec.json` 的原始描述、标识、语言和状态；
- 项目规则与当前权威资料；
- 真实源码、测试、配置、依赖和 API；
- 当前 Graphify 查询（扫描根覆盖目标时）；
- 本门禁和 Agent 定义。

### 必须发现

- 核心目标和旅程；
- 范围与相邻责任；
- 现有资产和必须保持行为；
- 数据、生命周期和废弃方案约束；
- 正常/异常/边缘/恢复路径；
- 用户/运营者可观察的非功能期望；
- 可测试性；
- 事实风险、歧义和未知。

先写 `validation-discovery-requirements.md`，核对文件存在且非空，才可读取目标。

### 阶段二

完整读取 `requirements.md`，逐项映射 discovery。检查数字 ID、EARS、覆盖、事实准确、范围、可测试性和实现泄漏。

输出 `independent-validation-report-requirements.md`。

## 三、design 模式

### 阶段一禁止读取

- `design.md` 的任何内容；
- 设计摘要、目录、片段；
- 从目标设计生成的任务或实现说明。

### 阶段一允许读取

- `spec.json`；
- 已独立 PASS 且哈希有效的 `requirements.md` 和报告；
- 项目规则、源码、测试、配置、依赖和启动脚本；
- `gap-analysis.md`（明确作为上游时）；
- 外部依赖的当前官方契约；
- 当前 Graphify 查询（覆盖目标时）。

### 必须发现

- 责任边界、数据所有权和依赖方向；
- 现有架构、扩展点和可复用能力；
- 真实文件、接口、模型、集合、端点和调用关系；
- 计划新增边界；
- 数据一致性、迁移和清理；
- 错误、恢复、观测、安全、性能和测试；
- 前端真实资产与设计边界；
- 外部依赖兼容性。

先写 `validation-discovery-design.md`，才可读取目标。

### 阶段二

读取 `design.md`/`research.md`，检查需求覆盖、边界、契约、文件规划、现有/新增区分、数据/状态、外部事实、迁移、测试、UI 和可实施性。

输出 `independent-validation-report-design.md`。

## 四、implementation 模式

实现校验可读取全部规格，但必须与实现上下文隔离。

检查：

- 任务状态与实际 diff；
- 需求和设计追踪；
- 测试实际运行；
- 旧实现清理；
- 技术栈/配置/文档联动；
- 启动与固定端口；
- 无关用户改动；
- 手动验收。

输出 `verification-report.md`。

## 五、证据规则

每个问题至少包含：

- 目标文档原文或章节（阶段二）；
- 项目/代码现实；
- 文件路径 + 行号或符号；
- 实际命令/测试（适用时）；
- 严重性；
- 修正方向。

`rg` 零结果只证明“在已说明的搜索范围内未找到”；核心不存在结论需结合目录、命名和调用方继续验证。

Graphify：

- 先核对 `.graphify_root`；
- 使用当前 `query/path/explain`；
- 引用 `source_location`；
- 源码复核；
- 不覆盖目标时使用 `rg`；
- 不依赖个人项目不存在的图谱服务。

## 六、分类与严重性

### 分类

- 匹配；
- 错误；
- 遗漏；
- 多余；
- 不可验证；
- 规则冲突；
- 过期证据。

### 严重性

- `critical`：错误方向、核心数据/安全/启动风险、核心范围缺失。
- `major`：重要行为、边界、契约、迁移或测试缺失。
- `minor`：不阻塞核心但需要修正。
- `info`：非问题建议。

## 七、PASS

全部满足：

- critical = 0；
- major = 0；
- 事实错误 = 0；
- 规则冲突 = 0；
- 虚构现有对象 = 0；
- 核心覆盖和追踪完整；
- 必需机械检查/测试通过；
- 目标哈希一致；
- 证据可复现。

minor 可记录后 PASS，但不得影响核心正确性。

## 八、FAIL

任一成立：

- 任意 critical/major；
- 任意事实错误、规则冲突或虚构现有对象；
- 核心遗漏或不可验证；
- 需求不可测试、设计不可实施；
- 必需测试失败/未运行；
- 显著设计或实现偏离；
- 旧实现残留；
- 启动约束破坏；
- 哈希不一致；
- 阶段一提前读取目标；
- 证据不足。

## 九、报告最小结构

- 规格、模式、时间；
- 目标路径与 SHA-256；
- discovery 路径与哈希；
- Git/工作树基线；
- 摘要；
- 方法和证据；
- 匹配、错误、遗漏、多余；
- 不可验证/规则冲突；
- 追踪表；
- 测试与机械检查；
- 分级问题；
- 修正项；
- 门禁理由；
- 精确结论。

不得删除 discovery；不得修改状态或目标。
