## 哲学

契约明确；最小化破坏性变更  
默认安全（认证优先、最小权限）

## 请求/响应

请求（典型）：  

{ "data": { ... }, "metadata": { "requestId": "..." } }  
成功响应：  

{ "data": { ... }, "meta": { "timestamp": "...", "version": "..." } }  
错误响应：  

{ "error": { "code": "ERROR_CODE", "message": "...", "field": "可选" } }  
（详见 error-handling 规则。）  

状态码（模式）  
2xx: 成功（200 读取、201 创建、204 删除）  
4xx: 客户端问题（400 验证、401/403 认证、404 不存在）  
5xx: 服务端问题（500 通用、503 不可用） 选择最能反映结果的状态码。  

## 认证

凭据放在标准位置  
Authorization: Bearer {token}  
业务逻辑前先拒绝未认证请求  

## 版本管理

通过 URL/头部/媒体类型进行版本控制  
破坏性变更 → 新版本  
非破坏性变更 → 同一版本  
提供弃用窗口和通知  

## 分页/过滤（如适用）

分页：page、pageSize 或基于游标  
过滤：显式查询参数  
排序：sort=field:asc|desc 在 meta 中返回分页元数据。  
关注模式和决策，而非端点目录
