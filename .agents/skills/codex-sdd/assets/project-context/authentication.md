# 认证与授权标准

> 使用边界：本文件只提供项目事实审计的结构提纲，不代表太初已采用其中的通用示例。只有现有项目规则、真实代码/测试/配置或用户明确决策支持的内容，才可增量写入对应权威资料；不得创建平行项目记忆文件。
[目的：统一认证模型、令牌/会话生命周期、权限检查和安全]  

## 哲学

明确分离：认证（谁）与授权（能做什么）  
默认安全：最小权限、失败时关闭、短期令牌  
用户体验感知：高风险处增加摩擦，否则保持流畅  

## 认证

### 方法（选择 + 理由）

选项：JWT、Session、OAuth2、混合  
选择：[我们的方法] 因为 [理由]  

### 流程（高层）

1) 用户证明身份（凭据或第三方提供商）  
2) 服务端验证并颁发令牌/会话  
3) 客户端每个请求携带令牌  
4) 服务端验证令牌并继续  

### 令牌/会话生命周期

存储：httpOnly Cookie 或 Authorization 头部  
过期：短期访问令牌，较长刷新令牌（如使用）  
刷新：轮换令牌；尊重吊销  
吊销：登出/泄露时列入黑名单/轮换  

### 安全模式

强制 TLS；避免将令牌暴露给 JS  
绑定令牌到受众/签发者；包含最少声明  
敏感操作考虑设备绑定和 IP/风险检查  

## 授权

### 权限模型

选择一种：RBAC / ABAC / 基于所有权 / 混合  
集中定义角色/属性；避免在代码库中硬编码  

### 检查位置（在哪里强制执行）

路由/中间件：粗粒度门控  
领域/服务：细粒度决策  
UI：条件渲染（无安全依赖）  

### 示例模式：

requirePermission('resource:action'); // 路由  
if (!user.can('resource:action')) throw ForbiddenError(); // 领域  

### 所有权

模式：所有者或特权角色可以操作  
变更前在实体边界验证  

## 密码与多因素认证

密码：强策略、哈希存储（bcrypt/argon2）、永不明文  
重置：限时令牌、单次使用、通知用户  
多因素认证：高风险操作升级验证（策略驱动）  

## API 间认证

使用 API 密钥或 OAuth 客户端凭据  
最小化密钥范围；轮换和审计使用  
按身份（用户/密钥）限速  
关注模式和决策，无库特定代码
