# PRD Spec Develop

## 定位

从功能点清单或规格名称出发，按 cc-sdd 流程推进规格开发。该 Skill 是编排器，具体阶段交给 `prd-to-ccsdd`、`prd-design-generator` 和 `prd-spec-impl`。

## 输入

- 规格名称：`{版本号}/{功能名}`，支持通配，例如 `V1.0/*`。
- 或功能点清单路径：`.kiro/plans/{版本号}/功能点清单.md`。

## 输入校验

1. 必须提供规格名称或功能点清单路径。
2. 功能点清单路径存在时，文件必须存在且非空。
3. 规格名称存在时，必须能在 `.kiro/specs/` 中匹配到目录；如果目录不存在，提示先执行 `prd-to-ccsdd`。
4. 匹配多个规格时，展示目录和阶段状态，等待用户确认批量执行范围。

## 规格状态

| 状态 | 判定 | 下一阶段 |
|---|---|---|
| 待创建 | 规格目录不存在 | 规格初始化 |
| 已初始化 | `spec.json` 存在，需求未完成 | 需求生成 |
| 需求已生成 | `requirements.md` 存在且审批通过 | 技术设计 |
| 设计已完成 | `design.md` 存在且审批通过 | 任务生成 |
| 开发中 | `tasks.md` 存在，实现未完成 | 继续实现 |
| 已完成 | `stage` 为 `completed` | 无 |

执行任何阶段前必须读取对应 `spec.json`，不得凭记忆假设状态。

## 流程

### Step 1 规格选择

根据输入生成规格清单，按状态分组展示。用户可选择一个、多个，或选择全部未完成规格。

### Step 2 规格初始化与需求生成

对选中规格使用 `prd-to-ccsdd`：

- 由 `prd-to-ccsdd` 按自身 references 执行初始化和需求生成。
- 生成 `requirements.md`。
- 询问是否执行 Gap 分析。

完成后展示摘要并等待用户确认。

### Step 3 技术设计

对选中规格使用 `prd-design-generator`：

- 生成 `design.md`。
- 询问是否执行设计评审。

完成后展示摘要并等待用户确认。

### Step 4 任务与实现

对选中规格使用 `prd-spec-impl`：

- 生成 `tasks.md`。
- 用户确认任务后执行 TDD 实现。
- 执行需求覆盖、设计一致性、全局遗漏验证。
- 更新 `spec.json` 并生成实现报告。

完成后展示实现报告并等待用户确认。

### Step 5 循环控制

本轮完成后统计：

- 已完成规格数量。
- 新增或修改文件数量。
- 已运行验证命令。
- 剩余未完成规格数量。

如果还有未完成规格，询问用户继续下一批或结束流程。

## 强制规则

- 严格按 Step 1 到 Step 5 执行。
- 每个 Step 完成后必须等待用户确认。
- 只处理 Step 1 中用户选中的规格。
- 实现阶段必须使用 `prd-spec-impl`，不得用临时 prompt 等价替代。
- 验证门禁不可跳过。
