# 阶段任务

更新日期：2026-07-05

## Phase 0：Preflight / 契约核对

目标：确认当前写作页按钮、AI 接口、LLM 工厂、知识库服务、AI 历史页面、测试命令。

允许修改：无。

禁止修改：禁止写业务代码，禁止提交。

任务：
1. 扫描写作页 9 个 AI 按钮。
2. 确认哪些按钮仍是假输出、mock 或前端拼接。
3. 确认现有 LLM 配置和 LLM client/factory。
4. 确认知识库读取服务和章节读取服务。
5. 确认 AI 历史/调用记录结构。
6. 列出与本任务包的差距。
7. 给出 Phase 1-6 的修改计划。

停机点：输出 Preflight 报告后停止。

---

## Phase 1：统一 AI 运行模型与记录

目标：建立真实 AI 调用的运行模型与持久化记录。

任务：
1. 定义 `WritingAIRun`。
2. 定义 `WritingAIButtonType`：chat、continue、polish、setting、suggestion、evidence、chapter_summary、inspiration、fact。
3. 定义 `WritingAIReferenceScope`：none、selection、chapter、full_text。
4. 定义 `PromptSnapshot`、`RetrievalContext`、`RetrievalEvidenceItem`、`WritingAIResult`。
5. 定义状态：queued、retrieving、calling_llm、parsing、completed、failed。
6. 实现 run 记录保存，必须包含 input、prompt_snapshot、retrieval_context、raw_llm_output、structured_output、error。
7. 不得只存 generated SQLite；若用 SQLite 做查询投影，主记录必须可导出或可重建。

停机点：模型和记录保存完成后停止。

---

## Phase 2：知识库检索与上下文构建

目标：所有按钮调用 LLM 前都必须构建章节上下文和知识库上下文。

任务：
1. 实现 `WritingAIContextBuilder`。
2. 读取当前章节、选区、选区前后文、本章节选。
3. 读取有效知识卡，不读取草稿、废弃、Inbox、未确认事实。
4. 第一版检索策略：名称/别名精确匹配 + 摘要/source_note/类型字段包含匹配 + 已有 FTS（如有）。
5. 知识库为空时记录 empty_reason。
6. 生成可注入 Prompt 的中文知识上下文。

停机点：上下文构建和测试完成后停止。

---

## Phase 3：真实 LLM 调用与固定 Prompt 接入

目标：接入真实 LLM，并让 9 个按钮使用固定 Prompt。

任务：
1. 建立 `WritingAIPromptRegistry`。
2. 将《04-固定Prompt模板.md》里的 9 个 Prompt 落地为不可临场修改的模板。
3. 每次渲染生成 `prompt_snapshot`。
4. 通过现有 LLM factory 调用真实 LLM。
5. 配置缺失返回 failed run，不返回假输出。
6. 解析 LLM JSON 输出。
7. 解析失败时保存 raw output 和中文错误。

停机点：后端能完成一次真实 LLM 冒烟调用后停止。

---

## Phase 4：统一 API 与前端按钮接入

目标：写作页 9 个按钮全部走统一后端 API。

API：
1. `POST /api/writing-ai/runs`
2. `GET /api/writing-ai/runs/{run_id}`
3. `GET /api/writing-ai/runs`
4. `POST /api/writing-ai/runs/{run_id}/replay`

任务：
1. 前端 9 个按钮全部调用 `POST /api/writing-ai/runs`。
2. 按钮传入固定 button_type 和合法参考范围。
3. 展示中文状态：检索中、调用模型中、解析中、完成、失败。
4. 根据 output_type 渲染结果。
5. 事实结果只进入 Inbox 待确认事实，不直接入库。
6. 设定结果不提供一键入库。

停机点：前端按钮全部接通后停止。

---

## Phase 5：AI 历史、评测与回放

目标：每次 AI 调用可检查、可回放、可定位错误。

任务：
1. AI 历史展示所有写作页 AI run。
2. 详情展示输入、参考范围、检索上下文、Prompt 快照、LLM 原始输出、结构化输出、错误信息。
3. Prompt 快照默认折叠。
4. replay 只回放已保存 trace，不重新调用 LLM。
5. 评测只检查链路，不做回答质量评分。

停机点：AI 历史和回放完成后停止。

---

## Phase 6：端到端验收与清理

目标：完成 9 个按钮的真实链路验收。

任务：
1. 用同一章节验证 9 个按钮。
2. 验证每次 run 有记录。
3. 验证 Prompt 快照完整。
4. 验证知识库上下文存在或有 empty_reason。
5. 验证前端无英文内部枚举。
6. 运行所有可用检查。
7. 更新执行说明。

停机点：返回最终证据，等待用户确认。
