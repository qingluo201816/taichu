# 阶段任务

> 更新日期：2026-07-04

## 通用阶段规则

每个阶段开始前必须确认：

```text
1. 已读取任务包文件和正文知识沉淀Agent方案.md。
2. 已确认当前阶段允许修改范围。
3. 已确认禁止事项。
4. 已说明本阶段最小执行计划。
```

每个阶段完成后必须：

```text
1. 运行本阶段要求的检查命令。
2. 按 03-证据返回模板.md 返回证据。
3. 停下来等待用户确认。
4. 不得自动 commit。
```

## Phase 0：Preflight / 文档与仓库状态确认

### 目标

只检查仓库与文档，不写业务代码。确认当前代码是否满足执行正文知识沉淀 Agent 的前置条件。

### 允许修改范围

```text
原则上不修改代码。
仅允许在用户明确要求时修正任务包路径说明或补充极小文档错字。
```

### 禁止修改范围

```text
src/taichu/**
web/**
project_assets/**
pyproject.toml
web/package.json
.env.example
```

### 具体任务

```text
1. 读取 AGENTS.md、docs/rule.md、TAICHU_DESIGN.md、正文知识沉淀Agent方案.md 和本任务包。
2. 检查旧 /chat 独立对话页是否存在。
3. 检查旧 /api/agents/chat 是否存在。
4. 检查当前是否已有 /agent-workbench。
5. 检查当前后端分层、Agent 注册、LangGraph 依赖、LLM 工厂、知识库模型、章节读取服务。
6. 检查当前 project_assets/source/knowledge/ 的知识卡结构是否为知识字段重构后的 v2 结构。
7. 检查当前是否已有 StructuredKnowledgeRepository 或类似抽象。
8. 检查运行命令是否可用：uv、ruff、mypy、前端 npm 脚本。
9. 输出阶段执行建议，但不进行实现。
```

### 停机点

输出 Preflight 证据后停止。若发现旧 `/chat` 或旧 `/api/agents/chat` 仍存在且影响实现，停止并列出清理建议，不得自行复活旧接口。

### 验收命令

```text
uv run python -m unittest discover tests
uv run ruff check .
uv run mypy
cd web && npm run lint
cd web && npm run build
```

如命令在修改前已失败，只记录失败，不归因本任务。

## Phase 1：后端模型、运行 JSON 中间态、KnowledgeRepository 抽象

### 目标

建立正文知识沉淀 Agent 的后端数据契约与存储边界，不接前端，不实现完整 LLM 流程。

### 允许修改范围

```text
src/taichu/domain/**
src/taichu/application/**
src/taichu/infrastructure/**
tests/**
```

### 禁止修改范围

```text
web/**
project_assets/source/**
不得引入 MongoDB
不得写入 source/knowledge 候选内容
不得实现前端页面
```

### 具体任务

```text
1. 新增或补齐 AgentRun、AgentRunNode、AgentLLMCall、AgentReviewItem、AgentMetrics 等模型。
2. 新增运行 JSON 中间态读写服务，目录固定为 project_assets/derived/agent_runs/knowledge_extraction/。
3. 文件名固定格式：extract_run_<YYYYMMDD_HHMMSS>_<短ID>.json。
4. 新增 KnowledgeRepository / StructuredKnowledgeRepository 抽象。
5. 第一版实现 JSONKnowledgeRepository。
6. Repository 必须提供：
   - list_active_cards(type?: string)
   - get_card(card_id)
   - create_active_card(card)
   - patch_active_card(card_id, updates)
   - search_active_identity(type, name, aliases)
7. list_active_cards 只返回 status=active 的知识卡。
8. draft、deprecated 不参与候选匹配。
9. 知识卡字段必须遵守知识字段 v2：无 body、tags、fields、confidence、source_refs、relations、foreshadow。
10. 类型专属字段直接保存在卡片顶层，不使用 fields 对象。
11. 写入 active 知识卡时 source_origin 必须存在，source_note 必须存在。
```

### 停机点

完成模型、Repository、JSON 中间态测试后停止，返回证据。

### 验收命令

```text
uv run python -m unittest discover tests
uv run ruff check .
uv run mypy
```

## Phase 2：LangGraph 主图与固定 Prompt 接入

### 目标

实现正文知识沉淀 Agent 的 LangGraph 主图骨架与固定 Prompt，不让 Codex 临场设计 prompt。

### 允许修改范围

```text
src/taichu/application/agents/**
src/taichu/application/services/**
src/taichu/infrastructure/llm/**
src/taichu/domain/**
tests/**
```

### 禁止修改范围

```text
web/**
project_assets/source/**
不得接 MongoDB
不得做 RAG
不得做向量库
不得做 GraphRAG
不得做后台队列
不得做 streaming
不得实现写作页入口跳转
```

### 具体任务

```text
1. 新增正文知识沉淀 Agent 模块，建议命名 knowledge_extraction。
2. 使用 LangGraph 实现主图，但 HumanReview 不放进 LangGraph interrupt/resume。
3. 实现节点：
   - LoadChapterNode
   - SegmentChapterNode
   - GeneralExtractionNode
   - MergeChapterCandidatesNode
   - TypeDispatchNode
   - CharacterExpertNode
   - EntityExpertNode
   - NormalizeAndValidateNode
   - RunInternalConflictCheckNode
   - MatchExistingKnowledgeNode
   - BuildReviewItemsNode
   - WriteIntermediateJsonNode
4. EventRuleExpertNode 只保留接口或占位，默认禁用。
5. 第一版处理范围只允许当前章节。
6. GeneralExtractionNode 只抽 character、location、faction、item。
7. CharacterExpertNode 禁止输出 personality、motivation、appearance、relations、current_goal、secret、known_secrets。
8. EntityExpertNode 只处理 location、faction、item。
9. Prompt 必须使用 05-固定Prompt模板.md 中的模板，不得临场改写核心硬规则。
10. 每次 LLM 调用必须记录完整 input_prompt、raw_response、parsed_output、model_name、prompt_version、duration_ms、error。
11. 产品运行用真实 LLM；测试可以注入 mock LLM。
12. LLM 返回非 JSON 时，节点标记 failed，run errors 记录原因，不吞错。
```

### 停机点

完成 LangGraph 主图、节点单测、mock LLM 测试后停止，返回证据。

### 验收命令

```text
uv run python -m unittest discover tests
uv run ruff check .
uv run mypy
```

## Phase 3：API 契约

### 目标

实现 `/api/agent-workbench/knowledge-extraction` 前缀下的运行、详情、候选审核接口。

### 允许修改范围

```text
src/taichu/api/**
src/taichu/application/**
src/taichu/domain/**
tests/**
```

### 禁止修改范围

```text
web/**
project_assets/source/** 测试外不得写用户数据
不得复用 /api/agents/chat
不得新增独立 metrics/logs API
不得做后台队列
不得做流式接口
```

### 具体任务

```text
1. POST /api/agent-workbench/knowledge-extraction/runs
2. GET /api/agent-workbench/knowledge-extraction/runs?page=1&page_size=20&status=all
3. GET /api/agent-workbench/knowledge-extraction/runs/{run_id}
4. GET /api/agent-workbench/knowledge-extraction/runs/{run_id}/candidates?status=pending&action=all
5. POST /api/agent-workbench/knowledge-extraction/candidates/{candidate_id}/confirm
6. POST /api/agent-workbench/knowledge-extraction/candidates/{candidate_id}/edit-confirm
7. POST /api/agent-workbench/knowledge-extraction/candidates/{candidate_id}/reject
8. POST /api/agent-workbench/knowledge-extraction/candidates/{candidate_id}/defer
9. confirm 规则：
   - create_card 写成 active 知识卡。
   - update_card 只补充已有 active 卡空字段，或追加 source_note，不覆盖已有非空字段。
   - conflict 不允许直接 confirm，必须 edit-confirm。
   - ignore 不允许 confirm。
10. edit-confirm 接收 card_updates 和 target_card_id。
11. 所有用户可见错误文本必须中文。
12. run detail 必须包含 nodes、llm_calls、review_items、metrics，不单独拆 metrics/logs API。
```

### 停机点

完成 API 与后端测试后停止，返回证据。


## Phase 4：前端智能体工作台

### 目标

新增 `/agent-workbench` 页面，实现正文知识沉淀 Agent 的工作台壳、运行任务、待处理候选、运行详情、评测指标四个 Tab。

### 允许修改范围

```text
web/src/app/agent-workbench/**
web/src/components/agent-workbench/**
web/src/lib/api/**
web/src/lib/types/**
web/src/app/** 导航入口相关最小修改
```

### 禁止修改范围

```text
src/taichu/** 除非 Phase 4 发现 API 字段明显缺失并先说明
project_assets/**
不得改写作页主流程
不得接 RAG
不得显示英文内部枚举
不得用游戏 UI、赛博霓虹、普通后台风
```

### 具体任务

```text
1. 新增 /agent-workbench 页面。
2. 按 TAICHU_DESIGN.md 使用午夜极光控制台风格。
3. 左侧：
   - Agent 列表：正文知识沉淀 Agent
   - 未来其他 Agent：占位或禁用
   - 最近运行列表
4. 中间固定四个 Tab：
   - 运行任务
   - 待处理候选
   - 运行详情
   - 评测指标
5. 右侧详情区：
   - 当前运行摘要
   - 当前候选详情
   - 当前 LLM 调用详情
   - 错误信息
6. 运行任务 Tab：
   - 选择当前章节
   - 点击“开始抽取”
   - 展示运行状态
7. 待处理候选 Tab：
   - 展示候选新卡、候选更新、候选冲突、建议忽略
   - 支持确认入库、编辑后确认、废弃、稍后处理
8. 运行详情 Tab：
   - 展示 nodes、llm_calls、errors
   - prompt/response 默认折叠，可展开查看
9. 评测指标 Tab：
   - 展示候选数量、schema 通过数、处理状态、耗时、LLM 调用次数等
10. 所有界面文案必须中文，英文枚举要映射为中文标签。
11. 主导航“智能体工作台”入口等页面可用后恢复。
```

### 停机点

```text

```

## Phase 6：端到端验收与清理

### 目标

跑通完整闭环，并清理无关旧入口、僵尸依赖、英文用户可见文案和越界实现。

### 允许修改范围

```text
全仓库内与本 Agent 闭环直接相关的最小修改。
```

### 禁止修改范围

```text
不得改 project_assets/source 用户数据，除非是在测试 fixture 中。
不得引入 MongoDB。
不得引入 RAG/向量库/ES/Neo4j/GraphRAG。
不得自动写入有效知识库。
```

### 具体任务

```text
1. 准备测试章节 fixture。
2. 执行当前章节抽取。
3. 生成 project_assets/derived/agent_runs/knowledge_extraction/*.json。
4. 打开 /agent-workbench 查看运行记录。
5. 查看待处理候选。
6. 确认一条 create_card 候选，写入 JSON active 知识卡。
7. 对一条 update_card 候选验证不覆盖已有非空字段。
8. 对 conflict 验证不能直接 confirm。
9. 验证 draft/deprecated 不参与匹配。
10. 验证写作页可通过知识库服务查询 active 卡。
11. 扫描用户可见英文文案。
12. 清理未使用代码和僵尸依赖。
```
