- `AGENTS.md`
- `CLAUDE.md`，如果仓库存在
- `docs/` 下与规则或知识库说明有关的文档
- `产品文档/` 下任务包或补充说明

### 禁止修改范围

- 不修改后端业务代码。
- 不修改前端业务代码。
- 不删除知识库 JSON 文件。
- 不改测试。
- 不改 package lock。

### 具体任务

1. 读取：`AGENTS.md`、`docs/rule.md`、`TAICHU_DESIGN.md`、`产品文档/MVP功能改版.md`、`产品文档/MVP迭代规则与LLM边界补充.md`。
2. 扫描：`project_assets/source/knowledge/`。
3. 扫描：后端知识库模型、schema、API、测试。
4. 扫描：前端知识库页面、知识卡组件、类型导航、表单字段。
5. 在项目实际使用的 Coding Agent 规则文档中加入规则：旧知识卡重构时直接清理，不保留、不迁移、不兼容。
6. 输出当前代码与本任务包的冲突点。

### 停机点

完成现状扫描和规则文档更新后停止，不进入 Phase 1。

### 验收命令

本阶段只需要文档检查。如仓库已有文档 lint，可运行对应命令；没有则说明未运行。

### 需要返回的证据

1. 已读取文件列表。
2. 当前知识库数据文件数量和目录分布。
3. 当前后端模型文件位置。
4. 当前前端知识库页面和组件位置。
5. 已修改的规则文档路径。

## Phase 1：数据清理与目录收敛

### 阶段目标

清空当前 `project_assets/source/knowledge/` 中已有旧知识 JSON 文件，删除不再进入第一版的伏笔类型目录或入口，建立新的知识库目录骨架。

### 允许修改范围

- `project_assets/source/knowledge/`
- 与知识库 fixture、测试数据有关的文件
- 数据初始化脚本或 seed 脚本
- 文档中记录知识库目录结构的部分

### 禁止修改范围

- 不修改写作编辑器。
- 不修改 AI 对话接口。
- 不实现真实 LLM。
- 不实现真实 RAG。
- 不做旧数据迁移。
- 不保留 foreshadow 兼容。

### 具体任务

1. 删除当前所有旧知识 JSON 文件，包括：
   - `character/*.json`
   - `event/*.json`
   - `foreshadow/*.json`
   - `item/*.json`
   - `worldbuilding/*.json`
   - 其他旧知识 JSON 文件
2. 删除或停止使用 `foreshadow` 作为第一版知识类型。
3. 建立第一版知识类型目录：
   - `character/`
   - `realm/`
   - `technique/`
   - `location/`
   - `faction/`
   - `item/`
   - `rule/`
   - `event/`
4. 确认不再使用 `worldbuilding/` 作为规则卡目录。规则卡统一进入 `rule/`。
5. 如果需要空目录占位，使用仓库既有约定；不要生成无意义旧知识卡。
6. 更新测试 fixture，避免测试依赖旧卡片。

### 停机点

完成数据清理和目录骨架后停止，不进入 Phase 2。

### 验收命令

- 后端单测命令，按仓库实际配置执行。
- 前端测试不强制，除非本阶段改动影响前端 fixture。

### 需要返回的证据

1. 删除的旧知识 JSON 文件列表。
2. 保留下来的知识库目录结构。
3. `foreshadow` 和 `worldbuilding` 是否已移除或停止使用。
4. 哪些测试 fixture 被更新。
5. 测试命令和结果。

## Phase 2：后端知识卡模型与 schema 注册表

### 阶段目标

建立新的知识卡字段模型和后端 schema 注册表。前端以后通过 schema 渲染编辑表单，不把字段结构写死在前端。

### 允许修改范围

- `src/taichu/domain/models/`
- `src/taichu/domain/rules/`
- `src/taichu/application/services/`
- `src/taichu/api/schemas/`
- `src/taichu/api/routes/knowledge*`
- 对应后端测试

### 禁止修改范围

- 不改 AI 对话主流程。
- 不改写作编辑器。
- 不改入口页。
- 不接真实 LLM。
- 不实现真实 RAG。
- 不恢复 `source_refs`。
- 不恢复 `foreshadow`。

### 具体任务

1. 新知识卡通用字段：
   - `id`
   - `type`
   - `name`
   - `aliases`
   - `summary`
   - `body`
   - `tags`
   - `importance`
   - `status`
   - `confidence`
   - `source_origin`
   - `source_note`
   - `fields`
   - `created_at`
   - `updated_at`
2. 废弃 `source_refs`，不要作为新结构字段保存。
3. 状态值采用实现默认：
   - `draft`：草稿
   - `active`：有效
   - `deprecated`：已废弃
4. 可信度采用实现默认：
   - `explicit`：正文明确写出或作者明确确认
   - `inferred`：推断
   - `uncertain`：不确定
5. 来源方式采用实现默认：
   - `inbox_fact`：来自 Inbox 待确认事实
   - `agent_extract`：来自正文/章节文本的 AI 自动抽取，第一版预留
   - `manual`：作者人工添加
6. 标记为有效时必须校验：
   - `name` 非空
   - `summary` 非空
   - `source_origin` 非空
   - `source_note` 非空
   - `source_note` 长度不超过合理限制，建议第一版不超过 1000 字
7. `source_note` 作为自由文本，允许写章节、原文摘要、人工说明等。
8. 建立后端字段 schema 注册表。schema 至少包含：
   - `field_key`
   - `label`
   - `field_type`
   - `required_when_active`
   - `options`
   - `placeholder`
   - `display_group`
   - `list_display`
   - `ai_usage`
9. 所有字段键名必须为英文正式字段名，不允许出现后端中文临时字段名。
10. schema 类型第一版支持：
    - text
    - long_text
    - enum
    - number
    - boolean
    - chapter_ref
    - knowledge_ref
    - string_array
    - record_array
11. 知识类型第一版只包括：
    - character
    - realm
    - technique
    - location
    - faction
    - item
    - rule
    - event
12. 不包括 `foreshadow`。

### 停机点

完成后端模型和 schema 注册表后停止，不进入 Phase 3。

### 验收命令

- 后端单测。
- 类型检查。
- lint。

### 需要返回的证据

1. 新知识卡模型文件路径。
2. schema 注册表文件路径。
3. 支持的知识类型列表。
4. 已删除或废弃的旧字段。
5. 标记有效校验规则。
6. 测试命令和结果。

## Phase 3：知识库 API 与校验规则

### 阶段目标

让知识库 API 能基于新模型创建、读取、更新、标记有效、标记废弃，并能提供 schema 给前端。

### 允许修改范围

- 知识库 API 路由
- 知识库服务
- 知识库存储适配
- 后端测试

### 禁止修改范围

- 不改前端 UI。
- 不改 AI 对话。
- 不做真实 RAG。
- 不做复杂关系图谱。
- 不实现物理删除。

### 具体任务

1. 提供获取知识类型列表 API。
2. 提供获取指定类型 schema API。
3. 提供按类型列出知识卡 API。
4. 提供创建知识卡 API。
5. 提供更新知识卡 API。
6. 提供标记有效 API。
7. 提供标记废弃 API。
8. 标记废弃不物理删除。
9. 常规“全部”列表不展示废弃卡，废弃通过“只看废弃”单独查看。
10. 搜索第一版只在当前选中知识类型内搜索，不做默认全类型混排。
11. 章节引用字段只接受章节稳定 ID，不接受展示序号作为事实保存字段。
12. 知识卡引用字段保存知识卡 ID，前端展示时解析名称。

### 停机点

完成 API 和测试后停止，不进入 Phase 4。

### 验收命令

- 后端单测。
- API contract 测试。
- lint/type check。

### 需要返回的证据

1. API 路径列表。
2. 每个 API 的输入输出摘要。
3. 校验失败场景测试。
4. 标记有效测试。
5. 标记废弃测试。
6. 搜索 scope 测试。
7. 测试命令和结果。

## Phase 4：前端 schema 驱动知识卡编辑界面

### 阶段目标

把知识库编辑界面改成基于后端 schema 渲染。前端只负责中文展示、交互、校验提示和表单布局，不硬编码每种卡片的全部字段结构。

### 允许修改范围

- `web/src/app/knowledge/`
- `web/src/components/knowledge/`
- `web/src/lib/api/knowledge*`
- `web/src/types/knowledge*`
- 前端测试

### 禁止修改范围

- 不改后端事实规则。
- 不直接读写 `project_assets`。
- 不使用英文内部枚举作为用户可见文案。
- 不恢复 `foreshadow` 页面入口。
- 不做关系图谱。
- 不做大表格编辑。

### 具体任务

1. 左侧类型导航只展示：角色、境界、功法、地点、势力、物品、规则、事件。
2. 移除伏笔入口。
3. 中间列表只展示当前类型知识卡。
4. 列表收缩态展示：名称、摘要、状态、重要程度、少量 `list_display` 字段。
5. 废弃卡默认隐藏，通过“只看废弃”查看。
6. 状态筛选为：全部、草稿、有效；废弃单独查看。
7. 详情区按分组展示：基础信息、类型字段、状态记录、来源说明。
8. 通用字段前端展示顺序：
   - 名称
   - 别名
   - 摘要
   - 重要程度
   - 来源说明
9. `tags` 前端第一版可以隐藏或放入不显眼的高级区域；如果隐藏，后端仍保留字段。
10. `created_at`、`updated_at` 前端隐藏，后端保留。
11. `source_origin` 前端显示为中文来源方式：
    - 来自 Inbox 事实
    - Agent 正文自动提取
    - 人工添加
12. `source_note` 前端显示为“来源说明”。
13. 章节引用字段用章节选择器选择稳定章节 ID，但展示章节名。
14. 知识卡引用字段用知识卡选择器保存 ID，但展示名称。
15. 字段为空时不要展示大面积空框，使用轻量占位或“添加字段”。
16. 所有用户界面不得出现英文内部字段名或枚举值。

### 停机点

完成前端知识库界面后停止，不进入 Phase 5。

### 验收命令

- `cd web && npm run lint`
- `cd web && npm run build`
- 若仓库存在前端测试，运行相关测试。

### 需要返回的证据

1. 修改的前端页面和组件列表。
2. 类型导航截图说明或文字说明。
3. schema 渲染路径说明。
4. 用户可见中文文案检查结果。
5. 废弃卡隐藏与“只看废弃”说明。
6. lint/build/test 结果。

## Phase 5：测试、验收与清理

### 允许修改范围

- 后端测试
- 前端测试
- 知识库相关文档
- 清理未使用代码

### 禁止修改范围

- 不新增新功能。
- 不接真实 LLM。
- 不做真实 RAG。
- 不恢复旧数据。
- 不恢复 foreshadow。

### 具体任务

1. 后端测试覆盖：
   - 创建草稿知识卡
   - 更新知识卡
   - 标记有效校验失败
   - 标记有效成功
   - 标记废弃
   - 废弃卡默认隐藏
   - 只看废弃
   - schema 返回
   - 章节引用保存稳定 ID
   - 知识卡引用保存 ID
2. 前端测试覆盖：
   - 类型导航无伏笔

   - 旧 `foreshadow` 导航和类型选项
4. 更新知识库字段说明文档。
