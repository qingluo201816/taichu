Kiro 命令调用规范
适用范围：所有 skill 中需要调用 kiro 命令的场景 目标：统一 kiro 命令的调用方式，禁止模拟命令效果，确保每个命令通过正确的 subagent 执行

一、核心原则
禁止模拟命令效果 — 不得用自己的理解模拟 kiro 命令的执行结果（如自编 spec.json 内容、跳过模板读取等）
禁止直接创建规格文件 — spec.json、requirements.md、design.md、tasks.md 等必须通过子 agent 生成
禁止跳过命令流程 — 每个命令有自己的完整流程（模板读取、名称检查、子 agent 调用等），必须完整执行
统一使用 general-purpose 子 agent — 所有 kiro 命令的执行统一使用 general-purpose 类型的子 agent，在 prompt 中加载 .claude/agents/kiro/ 下对应的 agent 定义和 .claude/commands/kiro/ 下的命令规范

三、调用模板
3.1 spec-init（无 subagent，主 agent 直接执行）
执行规格初始化，严格遵循 .claude/commands/kiro/spec-init.md 中的指令。

【参数】规格名称: {版本号}/{工号}/{大需求模块名称}
【返回】执行状态、生成的文件路径、规格名称
【日志】写入 progress.log — [时间戳] info stage_change 规格目录初始化完成 | stage: init
3.2 spec-requirements
使用 Agent 工具创建子 agent 执行需求文档生成。

subagent_type: general-purpose
description: "执行 spec-requirements"
prompt: |
  你是一个 kiro 需求分析专家。请严格按以下步骤执行：

  1. 读取 Agent 定义文件 .claude/agents/kiro/spec-requirements.md，理解角色职责和行为规范
  2. 读取命令规范 .claude/commands/kiro/spec-requirements.md，严格遵循其中的指令执行
  3. 执行 spec-requirements 命令
  4. 写入进度日志：追加一行到 progress.log — [时间戳] info stage_change 需求文档生成 | stage: requirements

  【参数】规格名称: {规格名称}
  【返回】执行状态、requirements.md 生成结果摘要

3.9 validate-independent
使用 Agent 工具创建子 agent 执行独立校验（需求或设计文档与代码一致性验证）。

subagent_type: general-purpose
description: "执行 validate-independent"
prompt: |
  你是一个 kiro 独立校验专家。请严格按以下步骤执行：

  1. 读取 Agent 定义文件 .claude/agents/kiro/spec-independent-validator.md，理解角色职责和行为规范
  2. 读取校验规范 .kiro/settings/rules/independent-validation-gate.md，严格遵循校验标准
  3. 执行 validate-independent 命令，mode={校验模式: requirements|design}
     - 阶段1：禁止读取目标文档全文，仅读取功能点清单标题，独立探索代码库
     - 阶段2：完成探索后才可打开目标文档做对比分析
  4. 写入进度日志：追加一行到 progress.log — [时间戳] info stage_change 独立校验完成 | stage: independent_validated

  【参数】规格名称: {规格名称}
  【校验模式】requirements（校验需求文档） | design（校验设计文档）
  【返回】
  - 执行状态: 成功 / 失败
  - PASS/FAIL 结论
  - 问题清单摘要（错误项、核心遗漏项）
  - 校验报告路径: .kiro/specs/{规格名称}/independent-validation-report-{mode}.md（mode=requirements 或 design）
3.10 编排 skill Agent prompt 模板
适用于 prd-spec-develop、prd-to-ccsdd、prd-design-generator 等编排类 skill 调用子 agent 时引用。

所有编排 skill 的子 agent prompt 共用以下结构，差异通过参数区分：

你是 {子skill名称} 的执行 agent。

【必须执行】使用 Skill 工具调用 {子skill名称} skill，传入以下参数：
- 规格列表: {selected_specs 逗号分隔}

【增量执行规则】对每个规格，先读取 .kiro/specs/{规格名}/spec.json 确认 phase：
- 按 phase 跳过已完成部分（各编排 skill 自行定义具体规则）
- phase = "requirements_done" 及之后: 跳过本 Step，返回"无需执行"

【独立校验门禁】文档生成后，必须执行独立校验：
1. 对每个选中的规格，使用 Agent 工具创建 spec-independent-validator 子 agent
   - subagent_type: general-purpose
   - prompt: 参照本文件第 3.9 节 validate-independent 调用模板，执行 mode={requirements|design} 校验
   - 参数: 规格名称={规格名}
2. 等待校验报告返回，读取 .kiro/specs/{规格}/independent-validation-report-{mode}.md
3. 如果校验 FAIL，展示错误项和遗漏清单，由用户决定退回修改或确认继续

【返回格式】
- 执行状态: 成功 / 失败
- 每个规格的处理结果摘要
- 独立校验报告路径及 PASS/FAIL 结论（如执行了校验）
- 关键产出文件路径
编排 skill 引用方式：在 Skill 文档中写明"参照 .claude/rules/KIRO_COMMAND_CALLING_SPEC.md 第 3.10 节"，不再内联完整 prompt。 各编排 skill 仅需定义自己的增量执行规则表格（phase 跳过规则 + 校验 mode 映射）。

四、Skill 引用方式
所有 skill 中涉及 kiro 命令调用的地方，统一写为：

参照 `.claude/rules/KIRO_COMMAND_CALLING_SPEC.md` 第 {章节号} 节的调用模板，
使用 general-purpose 子 agent 执行 {命令名称}，prompt 中加载对应 agent 定义和命令规范。
禁止：

不要内联完整的 agent prompt（模板已定义）
不要自行指定 File patterns（由命令文件决定）
不要使用自定义 subagent_type（如 spec-requirements-agent），必须使用 general-purpose
五、流程日志规范
每个规格目录下必须维护 progress.log 文件，记录完整的阶段流转历史。每次阶段状态变更必须追加一行日志。

日志路径：.kiro/specs/{规格名}/progress.log

日志格式：

[YYYY-MM-DDTHH:MM:SSZ] info stage_change {操作描述} | stage: {当前阶段}
写入规则：

追加到文件末尾，若文件不存在则创建
每次阶段变更只写一行，不重复记录
时间戳使用 UTC ISO 8601 格式
各阶段对应的日志条目：

阶段	操作描述	stage 值
spec-init	规格目录初始化完成	init
spec-requirements	需求文档生成	requirements
需求审批通过	需求文档审批通过	requirements_approved
spec-design	设计文档生成	design
设计评审通过	设计文档评审通过	design_approved
spec-tasks	任务清单生成	tasks
spec-impl	代码实现完成	implementation
validate-impl	实现验证通过	completed
六、用户提示中的命令引用
在展示给用户看的提示文本中（非执行逻辑），可以保留 /kiro:xxx 格式，告知用户可以手动执行的命令。例如：

> 接下来请执行 `/kiro:spec-design` 开始单个规格的设计阶段。
这是用户提示，不是执行逻辑，保留原格式。
