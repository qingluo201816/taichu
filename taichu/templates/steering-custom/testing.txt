测试标准
[目的：指导测试内容、测试位置和测试结构]

哲学
测试行为，而非实现
偏好快速、可靠的测试；最小化脆弱的 Mock
深度覆盖关键路径；广度优先而非追求 100%
组织
选项：

同置：component.tsx + component.test.tsx
分离：/src/... 和 /tests/... 选择一种作为默认值；允许有理由的例外。
命名：

文件：*.test.* 或 *.spec.*
测试集：被测对象；用例：预期行为
测试类型
单元测试：单个单元，Mock 依赖，非常快
集成测试：多个单元一起，仅 Mock 外部
E2E 测试：完整流程，最少 Mock，仅用于关键路径
结构（AAA）
it('当 Y 时执行 X', () => {
  // Arrange（准备）
  const input = setup();
  // Act（执行）
  const result = act(input);
  // Assert（断言）
  expect(result).toEqual(expected);
});
Mock 与数据
Mock 外部（API/数据库）；永不 Mock 被测系统
使用工厂/夹具；测试间重置状态
保持测试数据最小化且意图明确
覆盖率
目标：[整体百分比]；关键领域更高
在 CI 中执行阈值；例外需要审查理由
关注模式和决策，工具特定配置放在其他地方
