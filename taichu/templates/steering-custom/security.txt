安全标准
[目的：定义安全态势，涵盖验证、授权、密钥和数据模式]

哲学
纵深防御；最小权限；默认安全；失败时关闭
在边界验证；按目标上下文清理；永不信任输入
分离认证（谁）和授权（能做什么）
输入与输出
在 API 边界和 UI 表单验证；执行类型和约束
根据目标进行清理/转义（HTML、SQL、Shell、日志）
偏好白名单而非黑名单；尽早拒绝，提供最少细节
认证与授权
认证：验证身份；颁发短期令牌/会话
授权：操作前检查权限；默认拒绝
集中化策略；避免在代码中重复检查
模式：

if (!user.hasPermission('resource:action')) throw ForbiddenError();
密钥与配置
永不提交密钥；存储在密钥管理器或环境变量
定期轮换；审计访问；最小范围
启动时验证必需的环境变量；缺失时快速失败
敏感数据
最小化收集；在日志中脱敏/清理；静态和传输加密
按角色/按需限制访问；跟踪对敏感记录的访问
会话/令牌安全
尽可能使用 httpOnly + secure Cookie；全链路 TLS
短期过期；刷新时轮换；登出/泄露时吊销
绑定令牌到受众/签发者；包含最少声明
日志记录（安全感知）
记录认证尝试、权限拒绝和敏感操作
永不记录密码、令牌、密钥、完整 PII；避免完整请求体
包含 requestId 和上下文以关联事件
头部与传输
强制 TLS；HSTS
设置安全头部（CSP、X-Frame-Options、X-Content-Type-Options）
偏好现代加密；禁用弱协议/密码
漏洞态势
偏好安全库；保持依赖更新
CI 中进行静态/动态扫描；跟踪和修复
教育团队常见漏洞类型；编码为上述模式
关注模式和原则，将具体配置链接到运维文档
