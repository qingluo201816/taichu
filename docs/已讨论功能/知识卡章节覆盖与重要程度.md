# 知识卡章节覆盖与重要程度

> 更新日期：2026-07-12  
> 状态：已确认待实现

## 讨论结论

知识卡不再由模型主观填写“重要程度”。统一维护可追溯的“出现章节数”，并根据其占当前小说已写章节总数的比例，派生出供前端展示和后续任务使用的重要程度。

## 字段与更新口径

- `出现章节数` 是知识卡字段，允许为空；历史卡或尚无可核验证据的卡显示为“待统计”。
- 知识沉淀运行必须为候选卡提供章节出现信息；作者确认后，由应用层更新正式知识卡。
- 统计单位是**不同章节数**，不是同一章内的词语出现次数。
- 新运行处理第 101 章或第 101—105 章时，应将有可靠原文证据的新章节并入该知识卡已记录的章节集合，再得到新的章节数；不得简单按批次数量累加，以免重复处理同一章节造成重复计数。
- 只有作者确认的知识卡及其有效证据可以进入统计。AI 不能直接写入 MongoDB。

## 重要程度的派生规则

设当前小说已写章节总数为 `T`，某知识卡的出现章节数为 `C`，覆盖比例为 `C / T`。

| 覆盖比例 | 前端展示的重要程度 |
|---|---|
| `C / T ≥ 50%` | 核心 |
| `20% ≤ C / T < 50%` | 重要 |
| `5% ≤ C / T < 20%` | 普通 |
| `C / T < 5%` | 次要 |
| `C` 或 `T` 不可用 | 待统计 |

例如小说当前已写 100 章时：出现 50 章及以上为“核心”，20—49 章为“重要”，5—19 章为“普通”，少于 5 章为“次要”。

“重要程度”应由上述规则派生，不作为模型自由生成、作者逐章手工填写或知识抽取结果间直接比较的主观字段。后续任务需要使用重要程度时，应读取派生结果；需要更细粒度策略时，也可直接使用出现章节数与覆盖比例。

## 效果评估边界

- 单章知识沉淀效果评估完全不评估“出现章节数”与“重要程度”。
- 批量评估也不将它们计入字段一致性、候选 F1、结构字段分或总分。
- 章节覆盖统计用于长期知识库演进与作者人工判断，不应用于判断单次抽取是否正确。

## 实现边界

当前正式知识卡不保存完整章节来源引用。落地时需要建立可重建的“知识卡—章节出现记录”派生层，以保存经确认的证据所对应的章节集合；它不是新的结构事实源，正式事实仍以 MongoDB 中 `lifecycle=confirmed` 的知识卡为准。

实现后应补充：候选审核确认时的去重更新、历史卡待统计状态、前端的重要程度展示，以及供后续任务读取的派生查询入口。
