# 通用 Agent Runtime 编排技术设计

> 更新日期：2026-07-14

本文展开阶段二的通用 Agent Runtime 编排设计及已经落地的后端边界。Runtime 面向任意规模的小说写作相关请求，承载高层编排 Agent 的理解、规划、调度和收敛循环；它不是只服务复杂写作任务的固定流水线。精确 Schema、状态枚举、接口字段和执行行为以代码为准，本文只维护职责、链路和仍待验证的技术设计。

后端实现与验证结果见 [`docs/历史/2026年7月14日通用写作助手运行时实现报告.md`](../历史/2026年7月14日通用写作助手运行时实现报告.md)，作者工作台实现结果见 [`docs/历史/2026年7月14日通用写作助手工作台实现报告.md`](../历史/2026年7月14日通用写作助手工作台实现报告.md)。

## 一、进入本阶段的前置条件

以下前置条件已经由阶段一能力层满足：

- 能力层技术设计中确认的十六个生产 Tool，均使用真实服务、真实数据和真实副作用完成独立契约验收。
- 能力层技术设计中确认的十二个专业子 Agent，均能在没有顶层 Runtime 时独立完成自身边界内的任务。
- 稳定的 Schema、调用协议、上下文传递和分层技术日志。
- 每个子 Agent 明确的模型角色、Tool 权限、输出校验和资源上限。

Runtime 验收必须调用真实能力，不用假 Tool、假 Agent 或专门为演示编排而创建的占位能力。

## 二、高层编排 Agent 与顶层 LangGraph

高层编排 Agent 是任务理解、规划和调度决策主体，负责维护全局目标、计划、关键上下文、依赖关系、执行节奏和质量收敛。它不作为设定、写作或审校等单点专家，也不会在阶段切换后永久交出全局控制权。

顶层 LangGraph 是承载高层编排 Agent 和任务运行状态的编排图，负责：

- 接收从一次事实询问、局部分析或修改到多章节规划与创作的任意规模写作请求。
- 形成或更新高层计划。
- 从已注册真实 Tool 和子 Agent 中选择当前所需能力。
- 选择直接回答、调用 Tool、调用单个子 Agent 或组织多能力执行图。
- 组织能力之间的顺序、并行和依赖关系。
- 维护全局目标、共享状态、中间产物和执行节奏。
- 在质量校验失败时执行有上限的修复或重规划。
- 进入人工中断、持久化或终止节点。

顶层图只依赖子 Agent 的稳定异步契约。子 Agent 内部是普通 Handler 还是 LangGraph 子图，不改变顶层调用方式。

Runtime 必须选择满足当前目标的最小充分路径：小请求不得被强制扩展成长流程；只有存在真实依赖时才创建多节点 DAG、并行分支、校验循环、人工中断或长期记忆读写。

Runtime 从注册表读取能力和权限，不在顶层图中硬编码“检索—写作—检查”等固定顺序。十二个专业子 Agent 只提供能力，高层编排 Agent 根据单次请求生成计划和调用关系。

## 三、异步编排与动态 DAG

Runtime 当前支持：

- 根据当前请求动态生成计划、节点和依赖，不从固定“检索—写作—检查—生成”模板复制任务图。
- 按明确依赖运行任务节点。
- 对无直接依赖的子 Agent 进行有上限并行。
- 根据执行结果动态增加校验、修复或人工审核节点。
- 对每个节点显式保存输入来源、上游产物和下游消费关系。
- 当计划失效、子 Agent 失败或校验不通过时进入有限重规划。

当前实现由高层编排 Agent 产出有类型计划，计划节点只引用已注册 Tool 或专业子 Agent。Runtime 校验能力名称和无环依赖后，按就绪节点批次异步执行；无依赖节点可在任务并发上限内并行。上游输出可通过显式字段绑定传给下游，专业子 Agent 的有类型中间产物引用也会沿依赖边传递。

## 四、有限循环和共享状态

- 所有修复、重试和重规划循环都必须有明确上限。
- 至少需要维护 `revision_count`、`tool_call_count` 和最大重试次数等计数。
- 达到上限后停止自动修复，将当前结果、失败原因和可选行动交给作者。
- 共享状态只保存全局目标、计划、关键上下文引用、有类型的中间产物引用和执行计数，不在每个节点复制无界的历史全量。
- 证据报告、剧情计划、场景计划、正文候选、修改提案和审查报告都以 `lifecycle=draft` 的中间产物保存，不因进入共享状态而成为正文或结构事实。

共享状态已经以通用 Runtime 独立运行记录落地，保存计划修订、节点状态、输入绑定后的确定输入、输出、中间产物引用、来源引用、校验问题和有限重规划计数。上下文压缩与运行时记忆仍待后续讨论。

## 五、外部访问与人工写入授权

### 1. 外部访问许可

外部研究 Tool 默认不可调用。Runtime 必须在用户明确要求联网、外部研究或核实外部资料时，记录明确意图并签发仅对本次任务有效的外部访问许可。

- 外部访问许可绑定任务、允许的 Tool、研究主题、有效期和调用预算。
- 只有 `external_research` 子 Agent 可以消费外部搜索与来源读取 Tool；其他专业子 Agent 接收它产出的研究报告，不直接取得外部访问权限。
- 高层编排 Agent 不得因为外部资料“可能有帮助”而自行扩大许可。
- 外部来源和研究报告都是参考材料，不自动成为小说事实或已确认知识。
- 用户未明确授权时，任何外部 Tool 调用都必须在执行前失败，而不是静默降级或隐式联网。

### 2. 写入授权

当任务需要持久化修改正文、章节、大纲、知识卡或设置时，Runtime 必须：

1. 接收专业子 Agent 生成的有类型写入提案。
2. 由高层编排 Agent 调用预览或确定性校验能力。
3. 暂停自动执行，并向作者展示 Tool、作用范围、修改差异和风险。
4. 将作者授权绑定到 Tool、资源范围、规范化输入哈希、有效期和允许使用次数。
5. 只有高层编排 Agent 可以在参数未变化且授权有效时调用写 Tool；专业子 Agent 不直接取得写权限。
6. 写 Tool 校验基础正文哈希或结构版本、幂等键和授权后执行真实持久化。
7. 保存授权、写入结果、新资源版本和后续恢复位置。

知识提案只作为中间产物保存。作者确认后，Runtime 才生成 `create_confirmed_knowledge` 或 `update_confirmed_knowledge` 的确定输入；不得把 Agent 原始输出直接交给 MongoDB。

当前后端已经在写 Tool 前保存确定输入、输入哈希、作用范围和二次确认要求，并进入人工中断；作者批准后才签发短期写入授权。服务重启后不会复用失效的进程内授权，而是依据检查点中保存的作者决定和原作用范围重新签发。工作台已经展示授权操作、中文作用范围、输入哈希和确定输入，并在高风险写操作前要求二次确认。

## 六、checkpoint/resume 与历史分支

Runtime 当前已经持久化：

- 任务生命周期状态。
- 当前计划、DAG 节点状态和完成进度。
- 中间产物、调用结果和人工授权。
- 关键上下文引用与正文内容哈希。
- 外部访问许可、外部研究调用结果和引用来源。

恢复历史检查点前必须核对相关章节正文哈希。如果正文已变化，Runtime 不得直接覆盖当前内容，必须进入重新校验、重规划或作者选择。

每次生命周期和节点批次变化都会原子保存独立 JSON 检查点。运行中断后会封存为可恢复失败状态，把未完成节点复位到安全位置；恢复时继续使用已完成节点结果，不重跑成功节点。正文哈希、结构版本、知识更新时间和幂等键继续由真实写 Tool 执行最终并发保护。历史分支和可视化回退仍待后续设计。

## 七、分层监控展示

- 主流程图只展示子 Agent、质量门禁、人工中断和持久化等关键节点。
- Tool 调用作为所属 Agent 节点的子记录默认折叠展示，不把每次读取、检索或计算展开为主图节点。
- 子 Agent 内部若使用 LangGraph，可在 Agent 节点下展开带命名空间的内部节点事件。
- 会修改正文、写入结构事实、需要作者确认或直接决定路由的 Tool，应提升为显式节点或人工中断边界。
- 外部访问许可、外部搜索和来源读取默认折叠在 `external_research` 节点下，但必须能查看授权范围、来源和调用状态。

通用 Runtime 监控不复用知识沉淀 Workflow 的业务日志、状态机或评测模型。

## 八、Runtime 生命周期

当前代码已经实现初始化、澄清、规划、执行、等待人工、校验、重规划、完成、失败、取消和超时等生命周期；精确枚举和值以代码为准。主要转移规则如下：

- `INIT`
- `CLARIFYING`
- `PLANNING`
- `EXECUTING`
- `WAITING_HUMAN`
- `VERIFYING`
- `REPLANNING`
- `COMPLETED`
- `FAILED`
- `CANCELLED`
- `TIMEOUT`

- 初始请求进入规划；信息缺口会实质改变结果时进入澄清并暂停。
- 计划通过能力与 DAG 校验后进入执行；写 Tool 在授权前进入等待人工。
- 执行结束进入校验；存在可修复缺口且未超过上限时进入重规划。
- 服务重启会封存活动任务的最近检查点，作者可从检查点恢复。
- 完成和取消不可恢复；失败与超时可根据剩余计划或重新规划恢复。

## 九、当前实现边界

- 已搭建顶层 LangGraph、高层编排 Agent、任务理解、动态路由、并行 DAG 调度、结果校验和有限重规划。
- 已实现澄清、写入授权的后端人工中断，以及检查点、恢复、取消、超时和独立事件流。
- 已提供同步执行、后台启动、列表、详情、恢复、取消、删除和事件流 HTTP API。
- 已提供通用写作助手作者工作台，支持任务目标、正文范围、直接上下文、约束、明确外部访问许可、后台执行、运行进度、澄清、写入授权、取消、历史运行和最终结果。
- 未实现 Runtime 记忆和上下文压缩。
- 未实现通用 Runtime 节点监控页面和专属效果评测。
- 没有新增假 Tool、假 Agent 或独立测试型执行器；自动化测试调用生产 Tool 和生产子 Agent。

## 十、待继续讨论

- 覆盖不同规模的 Runtime 验收任务矩阵，包括小型事实询问、单能力任务、多能力组合任务和多章节长任务；这些任务只用于验证动态编排，不作为能力拆分模板。
- 真实模型下顶层计划 Schema 和输入绑定提示的稳定性。
- LLM 规划与确定性规则混合路由的收益边界。
- 不同任务长度下的并发上限、超时、部分失败和恢复成功率。
- 人工中断、授权差异展示和恢复交互的页面契约。
- Runtime 记忆与检查点之间的职责边界。
- 最大稳定任务步数和不同任务长度的评测方法。
