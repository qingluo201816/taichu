# 阶段 04：运行时记忆与上下文压缩

> 更新日期：2026-07-17  
> 阶段编号：`P04`  
> 依赖：`P01=PASS`；`P03` 可为 PASS、NO-GO 或 SKIPPED  
> 默认连续执行：是

## 一、阶段目标

为通用 Agent 建立专属记忆层，使其在长任务和多轮交互中能够：

- 结构化保存作者约束、已做决定、任务结论、未解决问题和来源引用。
- 在新一轮规划和校验前检索相关记忆。
- 以固定预算组装上下文。
- 对长对话和长节点结果做可追溯压缩。
- 在 checkpoint/resume 后重建同一上下文。
- 允许作者查看、拒绝、删除和继续会话。

写作区单步任务和知识沉淀 Workflow 不强制接入该记忆层。

## 二、必须分开的三层

### 1. Checkpoint

保存“任务执行到哪里、哪些节点成功、如何恢复”。它是执行状态，不承担跨任务知识学习。

### 2. Runtime Memory

保存“当前会话和相关运行中需要继续使用的约束、决定、结论和引用”。它用于上下文承接，不是小说事实。

### 3. Operating Experience

保存“多次任务后总结的高价值执行路径和失败模式”。它属于阶段 07，不能在本阶段直接影响生产策略。

## 四、记忆契约

建议 `AgentMemoryEntry` 至少包含：

- `memory_id`
- `lifecycle=draft|confirmed|rejected`
- `scope=run|conversation|runtime`
- `kind`
  - `author_constraint`
  - `decision`
  - `task_conclusion`
  - `unresolved_issue`
  - `fact_reference`
  - `artifact_reference`
  - `execution_summary`
  - `human_correction`
- `content`
- `source_refs`
- `artifact_refs`
- `run_ids`
- `conversation_id`
- `retention_priority`
- `created_at` / `updated_at` / `expires_at`
- `supersedes_memory_id`
- `content_sha256`
- `sensitivity`

不要使用知识卡已废弃字段来暗示记忆也是知识卡。记忆模型和 Mongo 知识 Schema 必须完全分离。

`fact_reference` 优先保存稳定来源 ID、字段路径和简短标签；需要使用事实时重新通过正文或统一召回读取。

## 五、任务清单

### `MEM-001` 增加会话身份

在 `GeneralAgentRun` 和 API 中增加：

- `conversation_id`
- `parent_run_id`
- `memory_refs`
- `context_snapshot_id`

要求：

- 不增加 `project_id`。
- 旧运行缺少 `conversation_id` 时，以 `run_id` 作为独立会话兼容读取。
- 新建任务可以创建新会话，也可以显式继续已有会话。
- 一个运行只能属于一个会话。
- 删除运行不自动删除作者明确保留的会话记忆；具体级联规则必须写清楚。

### `MEM-002` 实现仓储与生命周期

`AgentMemoryRepository` Protocol 至少支持：

- append/save。
- 按 ID 读取。
- 按 conversation、kind、lifecycle、时间查询。
- 标记 confirmed/rejected。
- 软删除或拒绝后默认查询排除。
- 过期清理。
- 按来源运行追溯。

JSON 写入使用临时文件与原子替换；索引损坏时可从记忆记录重建。

### `MEM-003` 实现受控写入策略

记忆不是任意 Tool。由 `AgentMemoryService` 在明确时点写入候选：

- 创建任务：作者硬约束。
- 作者澄清：新增事实需求或约束。
- 计划完成：关键决定和未解决项。
- 节点完成：只保存有后续价值的产物引用，不复制所有输出。
- 校验完成：任务结论和后续项。
- 作者修正：保存 `human_correction` 候选。

LLM 可以返回结构化 `MemoryWriteCandidate`，但服务必须校验：

- 允许的 kind。
- 内容长度。
- 来源。
- 作用范围。
- 重复/冲突。
- 敏感信息。
- 生命周期。

默认 LLM 生成内容为 `draft`。作者明确偏好或修正可在 UI 确认后成为 `confirmed`，但仍不是小说事实。

### `MEM-004` 实现记忆检索

第一版使用确定性过滤与词法排序即可：

- 先按 conversation、kind、lifecycle、时间过滤。
- 作者约束和未解决问题具有固定优先级。
- 查询文本、当前目标和能力节点用于相关性排序。
- 相同输入返回稳定顺序。
- top-k、字符预算、年龄衰减和去重可配置。

若阶段 03 已有稳定向量能力，可以在生成索引中增加记忆向量实验，但不得与知识召回索引混用，也不得成为本阶段上线前置。

### `MEM-005` 建立 ContextAssembler

在每次 `plan`、`replan` 和 `verify` 前构造 `GeneralAgentContextEnvelope`。建议顺序：

1. 系统硬规则。
2. 当前用户目标。
3. 当前作者硬约束。
4. 当前正文范围和直接上下文。
5. 相关权威事实引用及按需读取结果。
6. 当前会话近期消息。
7. 相关已确认记忆。
8. 当前运行计划、节点摘要和中间产物引用。
9. 未解决问题。
10. 输出 Schema。

每一类有独立预算和截断策略。记录：

- 输入字符/Token 估算。
- 每类选择数。
- 被压缩/丢弃原因。
- memory IDs 和 source refs。
- 策略快照。

不再把无限增长的全部 `messages`、所有节点完整输出和能力目录无条件塞入每次 Prompt。

### `MEM-006` 上下文压缩

触发条件：

- 估算上下文超过模型/策略预算。
- 消息数量超过阈值。
- 节点输出超过阈值。
- 恢复长任务时需要稳定摘要。

压缩结果使用结构化 `ContextDigest`：

- 当前目标。
- 作者硬约束。
- 已确认决定。
- 已完成节点及结论。
- 事实来源引用。
- 未解决问题。
- 下步条件。
- 被省略项统计。
- 原始来源 ID。

压缩可以使用独立 `memory_compactor` 模型角色，但必须：

- 使用结构化输出。
- 保留不可丢失字段。
- 经过确定性后校验。
- 失败时退回截断前的安全最小上下文，而不是生成空摘要。
- 不把摘要当事实。

### `MEM-007` 接入 Runtime 与 checkpoint

修改：

- `general_agent/orchestrator.py`：接收组装后的上下文，不自行拼接全部历史。
- `general_agent/service.py`：在生命周期节点调用记忆和上下文服务。
- `general_agent/executor.py`：InvocationContext 只传必要上下文引用和预算。
- `GeneralAgentRun`：保存 `memory_refs`、`context_snapshot_id` 和压缩统计。
- checkpoint：保存所用记忆 ID、生命周期、内容哈希和上下文策略快照。

恢复时：

- 优先使用 checkpoint 冻结的上下文快照。
- 若引用已被作者拒绝/删除，进入重新组装并记录差异。
- 不因记忆变化重跑已成功节点。
- 不复用其他 conversation 的记忆。

### `MEM-008` 作者工作台与管理入口

前端任务：

- 新任务可选择“继续当前会话”或“新会话”。
- 运行详情显示本次使用的记忆数量和压缩状态。
- 记忆详情按需展开，默认不显示完整技术 JSON。
- 作者可确认、拒绝、删除记忆。
- 明确标注“运行记忆不是小说知识库事实”。
- 所有文案中文，遵循 `DESIGN.md` 与 UI Skill。
- 不新增移动端适配和品牌化称呼。

### `MEM-009` 评测与基准

扩展通用 Agent 评测：

- 10 轮约束承接。
- 30 轮长会话压缩。
- 作者修正覆盖旧决定。
- 同名实体但不同会话隔离。
- 事实记忆必须重新取证。
- 记忆删除后不再消费。
- 恢复前后上下文一致。
- 上下文预算触发但硬约束零丢失。
- 无关记忆不应进入 Prompt。
- Token、费用、延迟变化。

## 六、验收门禁

- 记忆与知识事实完全分离。
- 旧运行可以读取。
- 新会话和继续会话都可用。
- 30 轮场景中上下文不超过配置预算。
- 作者约束、来源引用、未解决问题零丢失。
- 记忆选择稳定可复现。
- checkpoint 恢复选择相同上下文，或明确记录因作者删除导致的差异。
- 写作区单步任务和知识沉淀 Workflow 行为不变。
- UI 能查看和删除记忆。
- 全量测试、前端、固定端口验证通过。
