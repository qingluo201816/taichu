# 阶段 04：运行时记忆与上下文压缩

> 更新日期：2026-08-22
> 阶段编号：`P04`  
> 依赖：`P01=PASS`；`P03` 可为 PASS、NO-GO 或 SKIPPED  
> 默认连续执行：是

## 一、阶段目标

为通用 Agent 建立专属记忆层，使其在长任务和多轮交互中能够：

- 以“新对话窗口”为会话边界，结构化保存当前会话后续请求仍需使用的摘要、过程状态和来源引用。
- 从会话内第一条请求开始组装上下文，后续每次请求在同一会话身份下更新结构化记忆。
- 以固定预算组装上下文。
- 对长对话和长节点结果做可追溯压缩。
- 依赖 LangGraph checkpoint（运行检查点）在中断后恢复待执行节点和同一上下文。
- 自动写入、自动过期运行记忆，并允许作者只读查看；不允许作者直接新增、修改或删除单条运行记忆。

写作区单步任务和知识沉淀 Workflow 不强制接入该记忆层。

## 二、必须分开的三层

### 1. Checkpoint（运行检查点）

由 LangGraph checkpointer（检查点存储器）保存“任务执行到哪里、哪些节点成功、如何从待执行节点恢复”。它是执行状态，不承担跨任务知识学习。

### 2. Runtime Memory

保存“当前会话和相关运行中需要继续使用的摘要、过程状态、未解决问题和引用”。它由系统自动维护，用于上下文承接，不是小说事实，也不存在作者确认生命周期。

### 3. Operating Experience

保存“多次任务后总结的高价值执行路径和失败模式”。它属于阶段 07，不能在本阶段直接影响生产策略。

## 四、记忆契约

建议 `AgentMemoryEntry` 至少包含：

- `memory_id`
- `kind`
  - `user_instruction`
  - `task_summary`
  - `resource_summary`
  - `work_note`
  - `unresolved_issue`
  - `fact_reference`
- `content`
- `source_refs`
- `artifact_refs`
- `run_ids`
- `conversation_id`
- `created_request_index`
- `expires_after_request_index`
- `retention_priority`
- `created_at` / `updated_at` / `expires_at`
- `supersedes_memory_id`
- `content_sha256`
- `sensitivity`

不要使用知识卡已废弃字段来暗示记忆也是知识卡。记忆模型和 Mongo 知识 Schema 必须完全分离。

运行记忆不保存整章原文或完整节点输出。读取章节、文件或长资源后，只把有后续价值的短摘要和稳定来源引用写入 `resource_summary`；需要使用事实时重新通过正文或统一召回读取。

## 五、任务清单

### `MEM-001` 增加会话身份

在 `GeneralAgentRun` 和 API 中增加：

- `conversation_id`
- `parent_run_id`
- `memory_refs`
- `context_snapshot_id`
- `request_index`

要求：

- 不增加 `project_id`。
- 一个“新对话”窗口对应一个稳定 `conversation_id`；同一窗口内每条用户请求分别产生一次运行，并按 `request_index` 从 1 递增。
- 页面中的“次”表示当前会话内用户请求次数；“轮”只表示一个新对话窗口，不用于计数单条请求。
- 旧运行缺少或误写 `conversation_id` 时，优先沿用其稳定 `task_id` 聚合；只有完全找不到会话线索时才以 `run_id` 作为独立会话兼容读取。
- 新建对话必须显式创建会话；继续对话必须显式携带已有 `conversation_id`。
- 一个运行只能属于一个会话。
- 删除整个会话时，其自动运行记忆退出有效上下文；删除单次运行不把同会话其他请求拆成新会话。

### `MEM-002` 实现可靠的自动记忆仓储

`AgentMemoryRepository` Protocol 至少支持：

- append/save。
- 按 ID 读取。
- 按 conversation、kind、时间和请求序号查询。
- 软删除后默认查询排除。
- 按时间或 `expires_after_request_index` 自动过期清理。
- 按来源运行追溯。

JSON 写入使用临时文件与原子替换；索引损坏时可从记忆记录重建。运行记忆没有 `draft|confirmed|rejected` 生命周期，也不等待作者确认；其替代、过期和清理只由 Runtime 策略负责。删除整个会话时允许系统级联清理该会话的运行记忆，但不提供单条记忆的作者删除能力。

### `MEM-003` 实现五层上下文与受控自动写入

每次模型调用按以下五层理解和维护上下文：

1. **稳定记忆**：通过 System Prompt 承载 Agent 身份、基本行为、安全准则和静态能力索引；保持稳定前缀。
2. **长期记忆**：从 Markdown 按需召回的跨任务用户偏好；会变化、可压缩并可在合适阶段重新召回，不放入 System Prompt。
3. **历史对话**：此前真实 user/assistant 对话的早期摘要、相关原文和近期原始消息，不包含工具与内部运行轨迹。
4. **工作记忆**：当前任务摘要、运行记忆、工具与子 Agent 结果、计划、节点状态、授权、错误和未解决问题。
5. **当前请求**：本次用户请求、范围和硬约束，必须独立保存且完整进入模型上下文。

模型输入固定按 `System Prompt → 长期记忆 → 历史对话 → 工作记忆 → 当前请求` 拼接。

记忆不是任意 Tool。`AgentMemoryService` 仅在明确时点自动写入：

- 收到请求或作者澄清：提取仍需延续的用户指令，修正覆盖旧指令。
- 节点完成：只保存有后续价值的资源摘要、来源引用或短工作笔记，不复制完整章节、文件和节点输出。
- 任务完成：保存有后续价值的任务摘要和未解决项。

服务必须校验允许的 kind、内容长度、来源、重复/冲突、敏感信息和过期策略。普通规划过程、一次性推理和可从来源重新读取的大段文本不得写入工作记忆。

### `MEM-004` 实现记忆检索

第一版使用确定性过滤与词法排序即可：

- 先按 conversation、kind、有效时间和有效请求序号过滤。
- 当前用户指令和未解决问题具有固定优先级。
- 查询文本、当前目标和能力节点用于相关性排序。
- 相同输入返回稳定顺序。
- top-k、字符预算、年龄衰减和去重可配置。

若阶段 03 已有稳定向量能力，可以在生成索引中增加记忆向量实验，但不得与知识召回索引混用，也不得成为本阶段上线前置。

### `MEM-005` 建立 ContextAssembler（上下文组装器）

从会话内第一条请求开始构造 `GeneralAgentContextEnvelope`，之后在每次 `plan`、`replan` 和 `verify` 前更新。封装必须显式包含：

1. `stable_memory`（稳定记忆）。
2. `long_term_memory`（长期记忆）。
3. `history_memory`（历史对话）。
4. `working_memory`（工作记忆）。
5. `current_request`（当前请求）。

当前请求始终完整保留；正文选区、请求范围和本次硬约束归入当前请求，不得先截断再交给上下文组装器。长期记忆与工作记忆职责分离，避免把运行状态沉淀成跨任务偏好。

每一类有独立预算和截断策略。记录：

- 输入字符/Token 估算。
- 每类选择数。
- 被压缩/丢弃原因。
- memory IDs（记忆标识）和 source refs（来源引用）。
- 策略快照。

不再把无限增长的全部 `messages`、所有节点完整输出和能力目录无条件塞入每次 Prompt。

### `MEM-006` 上下文压缩

触发条件：

- 估算上下文超过模型/策略预算。
- 消息数量超过阈值。
- 节点输出超过阈值。
- 恢复长任务时需要稳定摘要。

预算不足时按固定顺序缩减，禁止平均裁剪：

1. 先收缩长期记忆。
2. 再压缩历史对话。
3. 再收缩工作记忆。
4. 稳定记忆与当前请求均不裁剪；如果仍超过总预算，明确报错要求缩小选区或拆分请求。

历史对话与工作状态的压缩结果使用结构化 `ContextDigest`：

- 当前目标。
- 当前用户硬约束。
- 有效任务决定。
- 已完成节点及结论。
- 事实来源引用。
- 未解决问题。
- 下步条件。
- 被省略项统计。
- 原始来源 ID。

压缩可以使用独立 `memory_compactor` 模型角色，但必须：

- 使用结构化输出。
- 保留不可丢失字段。
- 经过确定性后校验。
- 失败时退回截断前的安全最小上下文，而不是生成空摘要。
- 不把摘要当事实。

### `MEM-007` 接入 Runtime 与 LangGraph checkpoint

修改：

- `general_agent/orchestrator.py`：接收组装后的上下文，不自行拼接全部历史。
- `general_agent/service.py`：在生命周期节点调用记忆和上下文服务。
- `general_agent/executor.py`：InvocationContext 只传必要上下文引用和预算。
- `GeneralAgentRun`：保存 `memory_refs`、`context_snapshot_id` 和压缩统计。
- LangGraph checkpointer：持久化线程检查点、待执行节点、父检查点链和中间写入；线程 ID 使用 `run_id`。
- 上下文快照：保存所用记忆 ID、内容哈希和上下文策略快照。

恢复时：

- 若 LangGraph 状态仍有待执行节点，使用同一 `thread_id` 从该节点恢复，不从图起点重跑。
- 优先使用 checkpoint 冻结的上下文快照。
- 若引用已被删除或自动过期，重新组装并记录差异。
- 不因记忆变化重跑已成功节点。
- 不复用其他 conversation 的记忆。

### `MEM-008` 作者工作台只读观察入口

前端任务：

- 新任务可选择“继续当前会话”或“新会话”。
- 首次打开页面自动载入最近会话；只有点击“新对话”才清空当前会话身份。
- 最近对话和当前会话统一显示“N 次”，表示该会话内已有 N 次用户请求。
- 运行详情显示本次使用的记忆数量和压缩状态。
- 记忆详情按需展开，默认不显示完整技术 JSON。
- 记忆详情显示自动写入请求序号和自动退出上下文的请求序号；不提供新增、修改、删除、确认或拒绝操作。
- 作者只能通过正常对话或 Human-in-the-loop（人工介入）节点修正 Agent；不得要求作者理解或维护底层记忆结构。
- 明确标注“运行记忆不是小说知识库事实”。
- 所有文案中文，遵循 `DESIGN.md` 与 UI Skill。
- 不新增移动端适配和品牌化称呼。

### `MEM-009` 评测与基准

扩展通用 Agent 评测：

- 同一会话内 10 次请求的约束承接。
- 同一会话内 30 次请求的长历史对话压缩。
- 作者修正覆盖旧决定。
- 同名实体但不同会话隔离。
- 事实记忆必须重新取证。
- 记忆被 Runtime 自动替代、过期或随整个会话清理后不再消费。
- 恢复前后上下文一致。
- 上下文预算触发但硬约束零丢失。
- 无关记忆不应进入 Prompt。
- Token、费用、延迟变化。

## 六、验收门禁

- 记忆与知识事实完全分离。
- 旧运行可以读取。
- 新会话和继续会话都可用。
- 30 次请求场景中上下文不超过配置预算。
- 当前请求始终完整；当前用户约束、来源引用、未解决问题零丢失。
- 记忆选择稳定可复现。
- LangGraph checkpoint 恢复待执行节点且不重跑成功节点；上下文变化时明确记录因删除或自动过期导致的差异。
- 写作区单步任务和知识沉淀 Workflow 行为不变。
- UI 只能查看自动运行记忆，不出现单条新增、修改、删除、确认或拒绝操作。
- 全量测试、前端、固定端口验证通过。
