## 一、阶段目标

强化现有 checkpoint/resume，而不是重建。重点解决：

- 只保存最新快照、旧修订不可回退。
- 写操作成功后检查点未落盘的崩溃窗口。
- 外部调用结果不确定。
- 授权、记忆、召回和模型策略在恢复时的一致性。
- 最大稳定节点数、并发度和任务长度没有实测支持表。

不宣称理论上的 exactly-once。目标是：

- 对可幂等、本地可对账操作实现“效果上一次”。
- 对无法确认的外部副作用进入明确对账状态。
- 任何情况都不静默重复写或覆盖。

## 二、当前事实

现有 `JsonGeneralAgentRunRepository`：

- 每个 run 一个 JSON。
- 临时文件写入后 replace。
- `checkpoint_revision` 递增。
- 旧修订被覆盖。
- 列表直接扫描 `*.json`。

现有 Runtime 会在节点开始和完成前后保存，但外部调用成功与 `nodes_finished` 之间仍有窗口。

## 三、目标存储格式

建议将运行升级为兼容的目录格式：

```text
project_assets/derived/general_agent_runs/
  <run_id>/
    latest.json
    checkpoints/
      000001.json
      000002.json
    journal.jsonl
    effects.jsonl
```

每个检查点包含：

- 存储格式版本。
- run ID。
- revision。
- 前一修订哈希。
- 当前内容哈希。
- 事件类型。
- 完整可恢复运行状态。
- 所用记忆、召回、模型和授权策略快照引用。
- 写入时间。

`latest.json` 是快速读取快照，`checkpoints/` 和 journal 是恢复证据。旧的 `<run_id>.json` 支持一次性读取迁移；迁移完成后不永久双写。

## 四、任务清单

### `CHK-001` 定义失败与副作用模型

新增结构化状态：

- `NodeAttempt`
- `EffectRecord`
- `CheckpointRecord`
- `RecoveryDecision`

副作用状态：

- `prepared`
- `started`
- `succeeded`
- `failed`
- `unknown`
- `reconciled`
- `requires_human`

每个节点执行有稳定 `attempt_id`。每个写 Tool 副作用记录：

- Tool。
- 输入哈希。
- 幂等键。
- 资源范围。
- 授权引用。
- 前置版本/哈希。
- 预期后置版本/哈希。
- 调用开始/结束。
- 可对账证据。

### `CHK-002` 升级仓储协议

扩展 `GeneralAgentRunRepository` 或增加专用 checkpoint Protocol：

- `save_checkpoint`
- `get_latest`
- `get_revision`
- `list_revisions`
- `append_effect`
- `list_effects`
- `repair_latest`
- `migrate_legacy_run`

写入步骤：

1. 写临时修订。
2. flush + fsync。
3. 原子 rename。
4. 更新 journal。
5. 原子更新 latest。
6. 发布事件。

针对 Windows 实际验证原子行为；目录 fsync 不支持时记录平台边界。

### `CHK-003` 检查点完整性与回退

- 每个修订建立哈希链。
- 启动时校验 latest。
- latest 损坏时从新到旧寻找最近有效修订。
- 单个旧修订损坏不阻断更早修订读取。
- 损坏记录进入监控和审计。
- 不静默删除证据。
- 恢复后创建新修订并说明来源。

### `CHK-004` 写 Tool 对账能力

为当前六个写 Tool定义对账策略：

- `apply_manuscript_patch`
- `create_novel_structure_items`
- `update_novel_structure`
- `delete_novel_structure_items`
- `create_confirmed_knowledge`
- `update_confirmed_knowledge`

对账应使用真实资源状态：

- Markdown 内容哈希。
- 章节/卷结构版本。
- 删除归档位置。
- 知识卡 ID、更新时间和预期字段。
- 幂等键记录。

建议通过独立 `SideEffectReconciler` 注册表实现，不把对账逻辑塞进 Runtime `if/elif`。新增 Tool 时必须声明副作用和对账策略。

### `CHK-005` 执行前后写入顺序

写节点推荐流程：

1. 冻结确定输入和授权。
2. checkpoint `effect_prepared`。
3. effect `started`。
4. 执行真实 Tool。
5. effect `succeeded`，保存返回摘要和资源后置证据。
6. checkpoint 节点成功。
7. 若在 4—6 崩溃，恢复先对账，不直接重试。

只读 Tool 和专业子 Agent 可以按可重试策略处理，但已成功节点仍不普通重跑。

### `CHK-006` 故障注入框架

新增测试/脚本，能在以下点强制终止进程：

- checkpoint 临时文件写入前。
- 临时文件写入后、rename 前。
- latest 更新前。
- 节点标记 running 后。
- Tool 请求发出前。
- 本地写入完成后、effect 成功记录前。
- effect 成功记录后、节点 checkpoint 前。
- 作者授权后、写入前。
- 记忆写入后、运行 checkpoint 前。
- 模型路由决定后、LLM 调用前。
- 向量索引切换中。

故障注入使用生产仓储和生产 Tool，不使用假 Tool。模型和网络可使用可控适配器，但副作用测试必须操作临时 Markdown/Mongo 测试库。

### `CHK-007` 恢复算法

恢复分类：

- 已成功且证据完整：复用。
- prepared 未 started：安全重试。
- started 且无结果：
  - 可对账则查询真实状态。
  - 无法对账则 `requires_human`。
- 已失败且可重试：按原策略和预算。
- 授权过期：基于原输入、原哈希、原资源范围重签；任何变化重新请求作者。
- 记忆被删除：重新组装上下文并记录差异。
- 模型不可用：按冻结路由策略允许的回退。
- 向量索引变化：对已完成节点不重跑；未执行召回按当前策略并记录快照差异。

### `CHK-008` 长链路基准

建立矩阵：

- 节点数：1、3、6、12、20、40。
- 并发：1、3、8。
- 重规划：0、1、3。
- 任务类型：只读、生成、审校、混合、含一次写入、含人工中断。
- 故障：无、节点失败、模型超时、召回回退、进程中断、写入不确定。

指标：

- 完成率。
- 正确收敛率。
- 恢复成功率。
- 重复副作用数。
- 人工介入率。
- 计划/执行/校验耗时。
- checkpoint 大小和写入 p95。
- Token、费用。
- 失败类型分布。
- 最大内存占用。
- 上下文压缩率。

基础设施确定性测试应 100% 通过；真实模型基准至少重复三次。

### `CHK-009` 动态支持上限

不要默认把 Schema 上限 40 当产品稳定上限。根据基准生成支持表：

- `recommended_max_plan_nodes`
- `recommended_max_concurrency`
- `recommended_max_runtime_seconds`
- 含写操作任务的更低上限。
- 可自动恢复和必须人工恢复的边界。

运行配置默认值调整必须由基准支持，并同步 UI 中文说明。

### `CHK-010` 监控与作者交互

节点监控增加：

- 当前 checkpoint revision。
- 可用历史修订。
- 恢复来源。
- effect 状态。
- 对账结果。
- `requires_human` 原因。
- 重复执行保护。
- 检查点损坏告警。

不向作者显示完整输入、Prompt 或正文副本。

### `CHK-011` 迁移与保留

- 为旧平面 JSON 提供显式迁移。
- 迁移前备份和校验。
- 迁移后列表、详情、恢复和删除保持兼容。
- 删除 run 时按规则删除其 checkpoint、effect 和事件，但保留被其他运行引用的 confirmed memory/experience。
- 定义修订保留数量/期限，至少保留关键生命周期和写操作边界。
- 不永久双写新旧格式。

## 五、验收门禁

- 所有故障注入点有预期恢复结果。
- 确定性本地写入零重复、零静默覆盖。
- 不确定外部结果进入对账/人工，不直接重试。
- latest 损坏可回退。
- 已成功节点不重跑。
- 授权不扩大。
- 旧运行迁移可逆且测试通过。
- 生成真实最大稳定节点/并发支持表。
- UI 和 API 能区分失败、可恢复、需对账和需人工。
- 全量门禁和固定端口通过。
