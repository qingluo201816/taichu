# 阶段 05：自适应模型路由

> 更新日期：2026-07-17

> 依赖：`P00=PASS`、`P04=PASS`

## 一、阶段目标

在现有 Right Code 多模型网关、模型目录、调用遥测和静态 `ModelRoleRouter` 之上，增加一个确定性、可审计、可回放的策略路由层。目标不是“每次随机换模型”，而是根据任务需求在质量、成本、延迟和可用性之间做受控选择。

## 二、保留与替换边界

保留：

- `LLMGatewayContract`
- `RightCodeLLMGateway`
- 模型目录和模型监控
- `AGENT_MODEL_ROLES_JSON` 的显式角色固定能力
- 每次请求显式携带 `model_id`
- 现有调用遥测

升级：

- `ModelRoleRouter.model_for(role)` 的静态默认逻辑
- 编排、子 Agent、记忆压缩和语义裁判的模型选择
- 故障回退
- 决策可观测和离线回放

## 三、建议结构

- `src/taichu/application/model_routing/models.py`
- `src/taichu/application/contracts/model_routing.py`
- `src/taichu/application/services/model_routing_service.py`
- `src/taichu/application/model_routing/policies.py`
- `src/taichu/infrastructure/model_routing/jsonl_decision_repository.py`

可以让 `ModelRoleRouter` 变成兼容门面，内部委托新服务；完成迁移后删除不再使用的旧逻辑，不能永久保留两套决策源。

## 四、路由契约

### `ModelRoutingRequest`

至少包含：

- 逻辑角色。
- 任务类型和阶段。
- 响应模式：text/json/stream。
- 预计输入和输出 Token。
- 上下文窗口需求。
- 任务风险等级。
- 质量等级：快速/平衡/高质量。
- 延迟预算。
- 费用预算。
- 是否需要强结构化输出。
- 是否需要推理/创作。
- 当前重试次数和上一错误类型。
- run、node、conversation 关联。
- 允许/禁止模型。
- 配置硬覆盖。

### `ModelRoutingDecision`

至少包含：

- `routing_id`
- 选中模型。
- 兼容候选和排序。
- 决策原因代码。
- 策略 ID/机器版本。
- 质量、费用、延迟和健康快照。
- 是否使用硬覆盖。
- 回退链。
- 创建时间。
- 决策输入哈希。

决策记录不得保存完整 Prompt。

## 五、确定性策略层级

按顺序：

1. 协议兼容过滤：JSON、流式、上下文窗口、模型状态。
2. 安全/任务限制：禁止模型、外部策略、裁判独立性。
3. 显式硬覆盖：用户或 `AGENT_MODEL_ROLES_JSON`。
4. 健康熔断：近期 429、超时、5xx、空响应和结构化失败。
5. 角色质量基准：当前评测集按角色的历史表现。
6. 费用与延迟预算。
7. 稳定 tie-break。

第一版禁止用另一个 LLM 做路由决策。路由权重放在受校验配置或代码策略中，并写入决策快照。

## 六、任务清单

### `MOD-001` 统一模型 Profile

从现有模型目录和调用遥测组合出应用层只读 Profile：

- 模型 ID。
- 支持协议。
- JSON/流式能力。
- 上下文窗口。
- 价格。
- 近期健康。
- 角色评测得分。
- 结构化输出失败率。
- p50/p95 延迟。

信息缺失时必须标记 unknown，不能用 0 冒充免费或无延迟。

### `MOD-002` 实现策略路由服务

提供：

```python
async def select(request: ModelRoutingRequest) -> ModelRoutingDecision
```

同一策略快照和输入应得到相同模型。任何动态健康指标必须带观察窗口和快照时间。

### `MOD-003` 实现健康状态与熔断

从现有 LLM usage 读取或聚合：

- 调用成功率。
- 429。
- 5xx。
- 超时。
- 空响应。
- JSON 解析/Schema 修复失败。
- 最近连续失败数。

熔断有：

- 打开条件。
- 半开探测。
- 冷却期。
- 手动禁用。
- 恢复记录。

不要把单次业务输出质量差直接当基础设施故障。

### `MOD-004` 实现兼容回退

仅对可安全重试的失败自动回退：

- 429。
- 超时。
- 5xx。
- 模型暂不可用。
- 空响应且没有外部副作用。

以下不自动换模型重试：

- 作者取消。
- 权限错误。
- 输入 Schema 错误。
- 业务事实冲突。
- 写操作结果不确定。
- 已产生不可逆外部副作用。

回退请求保持 system/user 角色分离、输入哈希和输出 Schema。

### `MOD-005` 接入模型角色

依次接入：

1. `orchestrator`
2. 12 个专业子 Agent
3. `memory_compactor`
4. 后续语义裁判角色

每次运行/节点保存 `routing_id` 和决策快照引用。恢复默认复用原决策；只有原模型不可用且策略允许时才走回退，并记录差异。

### `MOD-006` 路由遥测与监控

保存到：

`project_assets/derived/model_routing/decisions.jsonl`

记录：

- 路由 ID。
- 角色。
- 选中模型。
- 候选数量。
- 原因代码。
- 硬覆盖。
- 预计/实际 Token、费用、耗时。
- 回退次数。
- 最终状态。
- 策略快照。

监控页面提供按角色、模型、状态、费用和回退筛选，默认不展开技术 JSON。

### `MOD-007` 离线回放与 A/B

使用：

- 通用 Agent 核心评测。
- 阶段 04 多轮/长上下文评测。
- 每个专业子 Agent 的评测 Profile。
- 历史脱敏调用统计。

对比：

- 固定默认模型。
- 静态角色映射。
- 自适应路由。

评估：

- 质量。
- 结构化成功率。
- 路由正确性。
- 安全。
- p50/p95。
- Token 和费用。
- 回退成功率。

### `MOD-008` 前端设置与透明度

- 继续支持显式固定某个角色模型。
- 显示“自动选择”与当前策略摘要。
- 运行详情显示实际模型和选择原因的中文摘要。
- 不显示供应商密钥和内部完整错误。
- 不允许并发任务通过全局“当前模型”互相影响。

## 七、验收门禁

- 显式固定模型始终优先。
- 核心安全评测零新增失败。
- 总体质量下降不超过 2 分。
- 低风险任务费用或 p50 延迟至少一项改善 10%。
- 故障注入回退成功率至少 95%。
- 决策可回放。
- checkpoint 保存路由快照引用。
- 静态路由可一键恢复。
- 全量测试、前端和固定端口通过。

## 八、自检

- [ ] 没有重写 LLM 网关。
- [ ] 没有用 LLM 选择 LLM。
- [ ] unknown 指标没有当 0。
- [ ] 显式覆盖不会被自适应策略绕过。
- [ ] 不安全错误不会自动换模型重试。
- [ ] 每次决策可解释、可回放。
- [ ] 并发任务没有全局可变模型。
- [ ] 路由结果进入 checkpoint。
- [ ] 质量、成本、延迟都与基线比较。
