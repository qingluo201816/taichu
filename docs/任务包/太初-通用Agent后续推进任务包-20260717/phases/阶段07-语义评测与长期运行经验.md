# 阶段 07：语义评测与长期运行经验

> 更新日期：2026-07-17  
> 阶段编号：`P07`  
> 依赖：`P05`、`P06` 达到可用结论  
> 默认连续执行：是

## 一、阶段目标

在现有五维确定性评测上增加经过人工校准的语义质量评测，并把真实节点流转、异常、人工介入和评测结果沉淀为可审核的长期运行经验。

该阶段建立的是 Agent 运维与策略知识，不是小说知识库。

## 二、长期运行经验与 Runtime Memory 的区别

Runtime Memory：

- 围绕一个会话/任务。
- 保存作者约束、决定、结论和来源。
- 直接服务上下文承接。

Operating Experience：

- 跨多次运行聚合。
- 保存高价值执行路径、失败模式、恢复方式、人工修正和策略收益。
- 默认只生成候选。
- 只有经过证据、评测和人工确认后才能影响 Prompt、路由、召回或编排策略。
- 永远不写入 MongoDB 知识卡。

## 三、语义评测任务

### `SEM-001` 扩展评测 Schema

在现有通用 Agent 评测模型中增加独立语义部分：

- 指令遵循。
- 事实一致性。
- 来源支持。
- 人物一致性。
- 世界设定一致性。
- 叙事结构。
- 场景张力。
- 文风与口吻。
- 修改任务的原意保留。
- 不确定性表达。

确定性分和语义分必须分开保存，不能用一个总分掩盖关键安全失败。

### `SEM-002` 建立人工标注集

至少覆盖：

- 事实问答。
- 人物分析。
- 世界设定。
- 宏观剧情规划。
- 场景计划。
- 新写正文。
- 改写/润色。
- 三类审校。
- 多轮记忆承接。
- 长链路任务。
- 写入授权与恢复。

每个样例由人工给出：

- 维度评分。
- 关键错误标签。
- 成对偏好。
- 是否可交付。
- 必须人工复核项。
- 参考说明。

标注集与盲测集分开，保存校验和。小说正文只保存必要来源引用，避免复制整章到评测结果。

### `SEM-003` 独立裁判角色

使用独立 `general_agent_semantic_judge` 角色：

- 不使用被评运行的同一模型作为默认裁判。
- system Prompt、rubric 和输出 Schema 冻结到评测记录。
- 裁判只读取必要的目标、约束、来源摘录和答案。
- 不读取隐藏的预期能力路径来“猜正确答案”。
- 支持重复采样和多数/中位聚合。
- 保存模型、路由决策、Token、费用和错误。

### `SEM-004` 校准

输出：

- Cohen’s kappa。
- Spearman 相关。
- 成对偏好一致率。
- 关键错误召回率和误报率。
- 重复运行一致率。
- 分模型/任务类型偏差。

达到总路线图门禁后，语义分才可参与自动策略比较。未达标时保留“辅助复核”，页面必须明确标注。

### `SEM-005` 防止评测污染

- 评测样例 ID 不进入生产 Prompt。
- 参考答案只在裁判阶段读取。
- 不能用同一批盲测样例反复手工调 Prompt 后仍称盲测。
- 数据集变更生成新校验和。
- 历史结果冻结旧 rubric 和参考答案。

## 四、运行经验任务

### `EXP-001` 定义经验候选

建议新增：

- `src/taichu/application/agent_experience/models.py`
- `src/taichu/application/contracts/agent_experience.py`
- `src/taichu/application/services/agent_experience_service.py`
- `src/taichu/infrastructure/agent_experience/json_repository.py`

`AgentExperienceCandidate` 至少包含：

- `experience_id`
- `lifecycle`
- 类别：成功路径/失败模式/恢复策略/人工修正/召回调优/路由调优/Prompt 调优/编排调优。
- 前置条件。
- 能力路径摘要。
- 结果。
- 失败或收益指标。
- 证据 run/evaluation/trace IDs。
- 人工修正。
- 适用范围。
- 禁用范围。
- 置信等级。
- 创建和更新时间。
- supersedes/rejected 原因。

避免使用与知识卡相同的 Schema 或集合。

### `EXP-002` 候选生成

从以下来源生成候选：

- 重复出现的高分最小路径。
- 相同失败类型超过阈值。
- 人工拒绝写入。
- 澄清问题被多次修正。
- checkpoint 对账。
- 向量召回增益/损失。
- 模型回退。
- 语义裁判与人工分歧。
- 作者对结果的显式修正。

候选生成只读取脱敏结构化数据。需要模型总结时输出结构化候选并保留证据，不直接成为 confirmed。

### `EXP-003` 去重、聚合和证据门禁

自动合并需要：

- 相同前置条件和失败指纹。
- 至少多个独立运行证据。
- 指标方向一致。
- 不跨不兼容任务类型泛化。

建议 confirmed 晋级最低条件：

- 至少 5 个独立运行证据，或 3 个高严重度一致故障。
- 离线回放显示明确收益。
- 安全评测无回归。
- 人工确认。

数量只是候选门槛，不代表自动正确。

### `EXP-004` 人工审核

提供紧凑审核界面：

- 候选类型。
- 证据运行。
- 指标前后对比。
- 适用和禁用范围。
- 建议影响的策略。
- 确认/拒绝/合并/废弃。
- 所有文案中文。

作者或开发者确认的是运行经验，不是小说事实。

### `EXP-005` 受控消费

confirmed 经验通过 `PolicyHintService` 生成只读提示：

- Prompt 补充规则。
- 召回策略候选。
- 模型路由权重候选。
- DAG 规划约束。
- 记忆读写策略。
- 恢复策略。

限制：

- 不直接改写 Prompt 文件。
- 不在运行时动态拼接所有经验。
- 每次消费有 hint ID、策略版本和证据。
- 先离线回放，再影子，再灰度。
- 一键禁用。
- 经验被 rejected/superseded 后停止新任务消费。

### `EXP-006` 经验评测

对每条策略提示比较：

- 采用前/后路径。
- 质量。
- 安全。
- 费用。
- 延迟。
- 失败率。
- 人工介入率。
- 恢复率。

不能只因某次任务成功就晋级经验。

## 五、数据目录与治理

- 记录：`project_assets/derived/general_agent_experience/`
- 索引：`project_assets/generated/general_agent_experience_indexes/`
- 语义评测：沿用 `derived/agent_evaluations/general_agent/`，增加校准报告子目录。
- 全部有 lifecycle、来源、校验和和脱敏规则。
- 定义保留期、归档、删除和引用完整性。
- 删除原运行时，若 experience 仍引用其证据，保留脱敏证据摘要或禁止删除并提示依赖；规则必须统一。

## 六、验收门禁

### 语义评测

- 达到 kappa、Spearman 和一致率门禁，或明确标记辅助复核。
- 关键事实/安全错误不能被高创作分抵消。
- 裁判独立。
- 校准集和盲测集分离。
- 历史结果可回放。

### 运行经验

- 候选不会自动影响生产。
- confirmed 需要证据、离线收益和人工确认。
- 经验与 Runtime Memory、小说知识完全分离。
- 每次策略消费可追溯、可禁用、可回滚。
- 没有把作者正文或完整 Prompt 复制到经验记录。
- 至少完成一个成功路径和一个失败模式的端到端闭环。

## 七、自检

- [ ] 语义裁判不是自评。
- [ ] 未校准分数没有用于自动晋级。
- [ ] 经验不是知识卡。
- [ ] 候选默认 draft。
- [ ] confirmed 有多个运行证据。
- [ ] 经验不能直接改 Prompt。
- [ ] 策略提示可禁用。
- [ ] 人工修正有来源和作用范围。
- [ ] 删除/归档规则明确。
- [ ] 页面不暴露完整 Prompt 或原文。

- 经验候选模型、仓储和生成器。
