# 前端风格切换任务

> 更新日期：2026-07-01
>
> 归档日期：2026-07-10。本文是历史任务快照，不再指导当前实现；文中的 `TAICHU_DESIGN.md` 当前已更名为根目录 `DESIGN.md`。

## 任务背景

太初已经进入“多套完整视觉风格的一键切换”方向。这里的切换不是简单白天/黑夜模式，也不是局部换色，而是“全站设计皮肤切换”：所有页面、组件、按钮、卡片、编辑器、资料页和 AI 状态在同一套布局与功能结构下，整体切换到另一种参考 design 的视觉语言。

当前默认主风格已替换为 `langbase-midnight-console`，即 Langbase 参考的午夜极光控制台风格。刚替换过的 `axiom-terminal` 纯黑橙色终端风格已移除，不再作为当前默认风格和可切换风格登记。

## 已确认选择

用户已确认以下边界：

- 允许每套风格修改颜色。
- 允许每套风格修改字体。
- 允许每套风格修改圆角。
- 允许每套风格修改边框。
- 允许每套风格修改阴影。
- 允许每套风格修改局部动效强度。
- 不允许每套风格修改页面信息结构。
- 不允许每套风格修改组件功能。

换句话说，风格包可以改变“看起来像什么”，但不能改变“页面有什么、功能怎么工作、信息如何组织”。

## 当前实现选择

当前采用“语义 token + 风格包切换”方案。

组件不直接使用某个具体风格名的 token，而是使用稳定的语义 token，例如：

```css
--tc-surface-page
--tc-surface-card
--tc-surface-panel
--tc-text-primary
--tc-text-secondary
--tc-text-muted
--tc-border-subtle
--tc-border-strong
--tc-action-primary-bg
--tc-action-primary-text
--tc-accent-brand
--tc-accent-highlight
--tc-radius-control
--tc-radius-card
--tc-radius-pill
--tc-shadow-card
--tc-font-display
--tc-font-ui
--tc-motion-fast
--tc-motion-normal
```

每一种风格只负责给这些语义 token 赋值。组件只关心“页面背景”“卡片背景”“主按钮”“弱边框”“正文颜色”等语义，不关心当前风格参考的是哪一个 design。

风格规则不建议全部写入根目录 `TAICHU_DESIGN.md`。多风格资料放入独立目录：

```text
docs/前端风格/
  索引.md
  午夜极光控制台风格.md
  石墨粉笔瑞士网格风格.md
  后续其他风格.md
```

根目录 `TAICHU_DESIGN.md` 只保留当前强制主设计规则和通用前端边界。各套可切换风格放在 `docs/前端风格/` 中单独维护，未来实现时再转译为 `web` 侧主题包。

## 技术实现

当前使用 HTML 属性控制风格：

```html
<html data-theme-style="langbase-midnight-console">
```

切换到另一套风格时改为：

```html
<html data-theme-style="graphite-chalk-swiss">
```

主题选择使用 `localStorage` 持久化，首次进入时使用默认风格。风格切换入口放在设置页，不放在首页。

当前相关文件：

```text
docs/前端风格/
  索引.md
  午夜极光控制台风格.md
  石墨粉笔瑞士网格风格.md

web/src/components/theme/
  theme-provider.tsx
  theme-switcher.tsx
  theme-registry.ts
  theme-script.tsx

web/src/app/globals.css
  基础语义 token
  [data-theme-style="langbase-midnight-console"] 风格赋值
  [data-theme-style="graphite-chalk-swiss"] 风格赋值
```

## 已登记风格

- `langbase-midnight-console`：当前默认主风格，详见 `docs/前端风格/午夜极光控制台风格.md`。特点是炭灰控制台、深色导航、灰色线框、白色胶囊按钮和极光装饰条。
- `graphite-chalk-swiss`：可切换风格，详见 `docs/前端风格/石墨粉笔瑞士网格风格.md`。特点是严格黑白灰、1px 发丝线、紧凑瑞士网格和单一黑色主按钮。

## 后续新增风格步骤

1. 在 `docs/前端风格/` 创建单独中文命名风格文档。
2. 在 `docs/前端风格/索引.md` 登记风格 ID、中文名称和状态。
3. 在 `web/src/components/theme/theme-registry.ts` 添加主题 ID、中文名称和说明。
4. 在 `web/src/app/globals.css` 添加对应 `[data-theme-style="..."]` 语义 token 映射。
5. 手动检查主要页面：入口、首页、编辑器、收件箱、知识库、对话、设置页。

## 重要约束

- 所有用户可见文案必须保持中文。
- 不复制外部参考产品的营销文案、客户 logo、下载平台语义或业务内容。
- 每套风格必须有明确 design reference，不允许随意拼贴。
- 布局结构和功能行为保持一致。
- 风格切换不能破坏编辑器输入、AI 卡片操作、来源证据、知识库阅读和设置页低频操作。
- 项目全局不允许负字距，因此即使参考设计存在负 tracking，太初实现也统一使用 `letter-spacing: 0`。
- 新增风格不得引入游戏 UI、赛博霓虹、普通后台管理系统或高饱和多色按钮体系，除非未来明确修改项目视觉边界。

## 验收标准

- 用户可以在设置页一键切换风格。
- 首页不放置风格切换按钮。
- 刷新页面后保留上次选择的风格。
- 所有主要页面同步切换，没有明显残留旧默认风格的页面或组件。
- 同一套风格内颜色、字体、圆角、边框、阴影和局部动效保持一致。
- 页面信息结构、路由、表单、AI 操作和数据行为不因风格切换改变。
- 文本对比度满足长时间阅读，尤其是编辑器正文、资料卡、来源证据和按钮文字。
