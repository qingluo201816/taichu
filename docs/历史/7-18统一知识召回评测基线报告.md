## 2. 生产边界与实现结果

- `RetrievalService` 仍是 AI 消费者读取确认态知识的统一入口，现支持已注册后端、消费方策略、硬预算、后端超时、结构化失败分支和显式回退。
- `MongoLexicalRetrievalBackend` 继续作为生产默认策略和确定性对照组，没有改变 MongoDB 是唯一结构事实源的决策。
- 身份匹配与目录快照强制使用 `mongo_lexical`，不会被相关性召回的策略配置改成非确定性后端。
- 服务层会对后端结果再次执行 `lifecycle=confirmed` 过滤；后续后端即使实现错误，也不能通过统一服务把草稿或已拒绝知识交给 AI 消费者。
- 四个知识 Tool 的名称、输入输出语义和业务边界保持不变。
- 章节摘要使用独立的 `chapter_summary` 策略档案；知识沉淀 Workflow、通用 Agent Runtime 和写作区单步任务继续各自使用明确的消费方档案。
- 评测模型与结果仓储位于召回专属命名空间，不复用通用 Agent 最终效果评分模型，也不把评测结果当作事实数据。
- `/task-monitor/retrieval/evaluation` 只读展示评测题目、历史基线、总体与分组指标、逐题结果和失败样例；页面消费的 HTTP API 不参与业务召回，也不能触发评测运行。

## 4. 兼容遥测与安全

新增或明确的机器可读字段包括：

- 策略：`policy_name`、`requested_strategy`、`effective_strategy`、`strategy_snapshot`。
- 回退：`fallback_used`、`fallback_reason_code`。
- 耗时：`backend_duration_ms`、`post_filter_duration_ms`。
- 快照：`index_snapshot_id`。
- 分支：每个后端分支的状态、候选数、命中数、耗时、错误代码和脱敏摘要。

旧 JSONL 缺少新字段时仍可读取。原始查询只转为长度和 SHA-256，不进入 trace；知识卡完整内容和向量也不进入 trace。遥测写入失败不会改变召回结果，后端不可用、超时或异常会留下明确分支记录；回退只有在真实执行后才标记为已使用。
