## 新结构化知识卡通用字段

当前前端知识库主要使用 `StructuredKnowledgeCard`。通用顶层字段如下：

| 字段 | 类型 | 含义 | 当前数据情况 |
| --- | --- | --- | --- |
| `id` | 字符串 | 卡片唯一 ID | 所有新结构卡片都有 |
| `type` | 枚举 | 知识类型 | 已出现 `character`、`event`、`foreshadow`、`item` |
| `name` | 字符串 | 知识卡名称 | 多数为空，已有“主角”“秦浩轩” |
| `aliases` | 字符串数组 | 别名 | 当前多为空数组 |
| `summary` | 字符串 | 摘要 | 当前多数为空 |
| `body` | 字符串 | 正文补充 | 当前多数为空 |
| `tags` | 字符串数组 | 标签 | 当前多为空数组 |
| `importance` | 枚举 | 重要程度：`core`、`major`、`normal`、`minor` | 已出现 `core`、`normal` |
| `status` | 枚举 | 状态：`draft`、`active`、`deprecated` | 已出现 `draft`、`deprecated` |
| `source_refs` | 来源数组 | 来源引用 | 部分角色卡有作者手动来源 |
| `fields` | 对象 | 类型专属字段 | 当前新结构卡片全部为空对象 |
| `created_at` | 字符串 | 创建时间 | 所有新结构卡片都有 |
| `updated_at` | 字符串 | 更新时间 | 所有新结构卡片都有 |

## 新结构化来源字段

`source_refs` 中每条来源引用当前模型字段如下：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `source_type` | 枚举 | 来源类型：`chapter`、`knowledge_card`、`author_note`、`external` |
| `source_id` | 字符串 | 来源 ID |
| `display_name` | 字符串 | 前端展示名称 |
| `excerpt` | 字符串 | 来源摘录，最多 300 字 |
| `note` | 字符串 | 备注 |
| `author_note_body` | 字符串或空 | 作者手动来源正文；当 `source_type=author_note` 时需要保留 |

## 旧 confirmed 知识卡差异

当前还有 1 个旧结构规则卡片位于 `project_assets/source/knowledge/worldbuilding/`。

该卡片顶层字段为：

```text
id, type, name, aliases, summary, fields, source_refs, status, created_at, updated_at
```

它与新结构化知识卡不同：

- 没有 `body`。
- 没有 `tags`。
- 没有 `importance`。
- `status` 使用 `confirmed`，而新结构使用 `draft`、`active`、`deprecated`。
- `fields` 实际包含 `pending_fact_id`、`text`。
- `source_refs` 使用旧来源锚点结构，字段包括 `source_type`、`source_id`、`path`、`chapter_id`、`anchor_type`、`paragraph_start`、`paragraph_end`、`char_start`、`char_end`、`excerpt`、`excerpt_hash`、`source_hash`、`created_at`、`stale` 等。

## 当前设计问题记录

- 新结构卡片的类型字段模型已经存在，但前端编辑界面目前主要编辑 `fields.note`，没有按类型展示专属字段。
- 当前实际新结构卡片的 `fields` 全为空，说明类型字段还没有真正沉淀为可用数据。
- 存在新旧两套知识卡结构：`StructuredKnowledgeCard` 和旧 `KnowledgeCard`。后续字段重设计时需要决定是否迁移旧 `confirmed` 卡片。
- 当前知识类型齐全，但实际数据集中在角色、事件、伏笔、物品和旧规则，境界、功法、地点、势力还没有实际卡片。
