# 项目规则

> 更新日期：2026-07-18

## 文件命名

- `docs/` 下除固定规则入口 `rule.md` 外，所有文档及其配套文件都必须带日期前缀，并以中文主题命名。
- 文件名统一使用 `月-日中文主题.扩展名`，月份和日期不补零，日期后不再添加分隔符，例如 `7-13通用智能体运行时编排技术设计.md`。
- 日期前缀取文档首次形成、首次讨论或归档日期；后续修订只更新文档内的“更新日期”，不反复改名。
- 同一文档的 Mermaid、PNG、SVG 等配套文件必须使用与文档一致的日期前缀和主题名。
- 文件名应清晰表达文件内容。

## 文档规范

- 每个文档必须包含**更新日期**
- 根目录 `README.md` 是唯一仓库地图；新增、移动或删除资料入口时必须同步更新。
- 同一主题只能有一个当前规则源；临时方案、任务记录和历史快照不得自称当前强制规则。
- `docs/临时架构/` 保存未完全落地、仍需核对代码或包含未来规划的架构资料。
- `docs/临时产品文档/` 保存尚未确认为当前产品契约的需求与规划。
- `docs/已讨论功能/` 保存用户在讨论中提出的需求、功能设想与决策；每份文档必须写明讨论日期和状态（讨论中、已确认待实现、已实现），不得把尚未落地的内容写成当前代码事实。
- 用户提出或确认会影响后续产品、字段、流程或评估口径的要求时，应在同一轮工作中新增或更新 `docs/已讨论功能/` 中对应的中文文档；实现后同步更新其中的状态与实现入口。
- `docs/历史/` 保存有追溯价值但不再指导当前实现的快照。
- 临时目录和历史目录中的文件以目录级说明为状态标记，不要求逐份重复声明。
- 代码枚举、Schema、主题 token 和接口字段以代码为准；文档说明职责和入口，不复制维护第二份完整定义。
- 不在持久文档中混入 `//` 形式的临时 AI 指令。
- 不创建或保留 `.gitkeep`；需要的目录由代码或工具按需创建。
