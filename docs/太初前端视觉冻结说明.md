# 太初前端视觉冻结说明

> 更新日期：2026-07-01

## 设计来源

本视觉基线以根目录 `TAICHU_DESIGN.md` 为强制规则源，适用于 `web/` 下页面、组件、样式、交互、动效和用户可见文案。旧版设计说明已归档到 `docs/太初旧版前端设计已废弃.md`，只用于历史追溯，不再作为当前实现依据。

## 当前视觉基线

太初前端当前默认主风格为“Langbase 午夜极光控制台风格”：

- 炭灰控制台画布用于主要页面、功能入口、资料阅读、设置和工作台背景。
- 深色导航条作为顶部稳定锚点。
- 灰色发丝线用于层级、分割和控件边界。
- Geist Sans 用于主要 UI 文本，Geist Mono 用于展示标题、技术读数和代码感标签。
- 白色胶囊按钮用于低频主操作。
- 极光渐变只用于少量装饰条、背景线索或 AI 状态氛围，不作为功能色。
- 卡片使用 12px 圆角，输入框和小标签使用 4px 圆角，按钮使用全圆角。
- 所有用户可见文案必须为中文，不能直接展示英文内部字段名、接口名或枚举值。

## Token 迁移状态

当前 `web/src/app/globals.css` 已建立以 `data-theme-style` 控制的语义 token 层。默认主题为 `langbase-midnight-console`，可切换主题放在 `docs/前端风格/` 中单独维护。

新增组件、新页面和自动前端任务必须优先使用语义 token：

- `--tc-surface-page`
- `--tc-surface-card`
- `--tc-surface-panel`
- `--tc-text-primary`
- `--tc-text-secondary`
- `--tc-text-muted`
- `--tc-border-subtle`
- `--tc-border-strong`
- `--tc-action-primary-bg`
- `--tc-action-primary-text`
- `--tc-accent-brand`
- `--tc-radius-control`
- `--tc-radius-card`
- `--tc-radius-pill`
- `--tc-font-display`
- `--tc-font-ui`
- `--tc-font-mono`

旧 token 可作为迁移期兼容层保留，但不得继续扩展已废弃视觉方向。

## 页面覆盖范围

- `/`：应作为太初写作助手的清晰入口，第一屏能识别品牌、单本玄幻小说写作场景和主要进入动作。
- `/home`：功能入口使用炭灰控制台画布、线框卡片和明确中文模块名。
- `/editor`：章节编辑、工具栏、资料辅助和 AI 操作遵循控制台工作台语言，优先保障输入效率。
- `/inbox`：灵感、待确认资料和 AI 内容片段以可归档控制台资料条目呈现。
- `/knowledge`：知识列表和详情以控制台档案库呈现，来源、状态和章节关系清晰可见。
- `/chat`：对话表单、结果正文和来源证据使用统一卡片与中文标签体系。
- `/settings`：风格切换、导出、重建、清理等低频操作保持清晰、克制、中文说明完整。
- `/dashboard`：如果保留，应与当前视觉基线一致，不单独创建新的后台风格。

## 组件覆盖范围

- `Button`、`Card`、导航、输入框、标签、弹层和状态提示应逐步迁移到当前语义 token。
- 主按钮使用白底黑字胶囊形，且每屏低频出现。
- 卡片默认使用炭灰表面、12px 圆角和 1px 线框。
- 输入框默认使用内凹深色背景、4px 圆角和灰色边框。
- 标签和徽标必须配中文文字，不得只靠颜色表达状态。
- AI 结果和来源证据必须显示中文操作与中文来源说明。

## 禁止随意修改的边界

- 不引入游戏 UI、赛博霓虹、普通后台管理系统或多色高饱和按钮体系。
- 不恢复 Axiom 纯黑橙色终端风格作为默认主风格。
- 不恢复旧版奶油纸张编辑出版风格作为默认主风格。
- 不把极光渐变作为按钮、文字、边框、图标或功能状态颜色。
- 不使用大面积渐变、玻璃拟态、强发光卡片或厚重阴影。
- 不隐藏 AI 卡片、PendingFact、Knowledge、来源证据的关键操作。
- 不把英文内部字段名直接作为用户可见文案。
- 不复制外部参考产品的营销文案、平台下载语义、客户 logo 或业务内容。

## 允许未来修复范围

后续视觉变更应限制为：

- 与根目录 `TAICHU_DESIGN.md` 一致的 token 迁移。
- 已登记风格包之间的语义 token 切换。
- 样式 bug 修复。
- 响应式适配。
- 可访问性改进。
- 性能优化。
- 组件库准入后的局部实现补齐。

不得在没有新设计确认的情况下更换整体视觉方向。
